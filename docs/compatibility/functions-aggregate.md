# Aggregate functions

Aggregate functions and grouping helpers.

Current ungrouped aggregate `SELECT` lists can mix supported aggregate items in
the documented one-table/no-source envelope with baseline `WHERE`, aliases, and
`LIMIT`; see [baseline multi-aggregate SELECT](../specs/baseline-multi-aggregate-select/specs.md).

The parser also admits common MySQL aggregate-window `OVER` syntax for the
current `COUNT(*)`, `COUNT(column)`, `COUNT(DISTINCT column)`, supported
row-scalar arguments for `SUM()` / `AVG()` / `MIN()` / `MAX()` / bitwise and
statistical aggregates, and `GROUP_CONCAT(...)`, plus JSON aggregate-window
placeholders such as `JSON_ARRAYAGG(...) OVER ...` and
`JSON_OBJECTAGG(...) OVER ...`. Execution of aggregate-window forms is explicitly
unsupported and returns a deterministic diagnostic. See
[parser aggregate window syntax](../specs/parser-aggregate-window-syntax/specs.md)
and [parser corpus aggregate/window surfaces](../specs/parser-corpus-aggregate-window-surfaces/specs.md)
and
[parser corpus JSON/statistical aggregate window surfaces](../specs/parser-corpus-json-stat-aggregate-window-surfaces/specs.md).

| `ANY_VALUE()` | 🟡 | Limited scalar and row-scalar transparent `ANY_VALUE(expr)` over already-supported scalar/row-scalar expressions, plus limited grouped `ANY_VALUE(column)` over descriptor-backed grouped sources where selected group columns are followed by aggregate-like results; grouped arguments are descriptor columns, representative values are arbitrary when a group contains different candidates, and selected aggregate aliases participate in the existing grouped `HAVING ... IS NULL` / `IS NOT NULL` and `ORDER BY alias [ASC\|DESC]` paths. No mixed ungrouped aggregate form, expression arguments in grouped use, `DISTINCT`, `*`, windows, DML/default/check/generated-column contexts, or deterministic representative-row selection |
| `AVG()` | 🟡 | Limited mixed ungrouped `AVG([DISTINCT] expr)` over one descriptor-backed persistent base table with optional source alias, source-qualified operands, baseline `WHERE`, aliases, `LIMIT`, literals, and supported row-scalar arguments, plus limited grouped `AVG([DISTINCT] expr)` over the current grouped source envelope; four-fractional-digit text results are produced while the intermediate signed-64 `SUM(expr)` stays in range. No exact decimal widening beyond the signed-64 intermediate envelope, full grouping, aggregate ordering, or executable window forms |
| `BIT_AND()` | 🟡 | Limited mixed ungrouped `BIT_AND(expr)` over one descriptor-backed persistent base table with optional source alias, source-qualified operands, baseline `WHERE`, aliases, `LIMIT`, literals, and supported row-scalar arguments, plus limited grouped form over the current grouped source envelope; numeric unsigned-64 semantics with neutral all-ones output for empty/all-`NULL` input and unsigned decimal text results. No `DISTINCT`, binary-string evaluation, bitwise result `HAVING` predicates, full grouping, aggregate ordering, or executable window forms |
| `BIT_OR()` | 🟡 | Limited mixed ungrouped `BIT_OR(expr)` over one descriptor-backed persistent base table with optional source alias, source-qualified operands, baseline `WHERE`, aliases, `LIMIT`, literals, and supported row-scalar arguments, plus limited grouped form over the current grouped source envelope; numeric unsigned-64 semantics with neutral `0` output for empty/all-`NULL` input and unsigned decimal text results. No `DISTINCT`, binary-string evaluation, bitwise result `HAVING` predicates, full grouping, aggregate ordering, or executable window forms |
| `BIT_XOR()` | 🟡 | Limited mixed ungrouped `BIT_XOR(expr)` over one descriptor-backed persistent base table with optional source alias, source-qualified operands, baseline `WHERE`, aliases, `LIMIT`, literals, and supported row-scalar arguments, plus limited grouped form over the current grouped source envelope; numeric unsigned-64 semantics with neutral `0` output for empty/all-`NULL` input and unsigned decimal text results. No `DISTINCT`, binary-string evaluation, bitwise result `HAVING` predicates, full grouping, aggregate ordering, or executable window forms |
| `COUNT()` | 🟡 | Limited `COUNT(*)`, `COUNT(integer/NULL/boolean literal)`, `COUNT(column)`, supported row-scalar `COUNT(expr)`, and `COUNT(DISTINCT column)` in documented no-source, one-table, mixed ungrouped, joined-count-star, and base-table and joined grouped forms; optional aliases, source aliases, source-qualified column arguments, baseline `WHERE`, selected grouped `HAVING`, and supported `LIMIT` envelopes are covered. The parser additionally admits unsupported `COUNT(DISTINCT expr[, expr...])` placeholders. No broad `COUNT(expr)`, broader joined non-star count forms, full grouping, aggregate ordering, or executable window forms |
| `COUNT(DISTINCT)` | 🟡 | Limited `COUNT(DISTINCT column) [AS alias]` in the mixed ungrouped one-table envelope and integer-descriptor base-table and joined grouped aggregate envelopes with optional source alias, source-qualified column argument, parenthesized descriptor-column form such as `COUNT(DISTINCT(table.column))`, baseline `WHERE`, and selected grouped `HAVING`; integer/`NULL` descriptor columns only. The parser additionally admits multiple-expression, literal, and expression-shaped `COUNT(DISTINCT ...)` placeholders and rejects unsupported execution deterministically. No executable multiple expressions, expression arguments beyond parenthesized descriptor columns, executable literals, string distinct semantics, broader grouping, aggregate ordering, or executable window forms |
| `GROUP_CONCAT()` | 🟡 | Limited mixed ungrouped and grouped `GROUP_CONCAT([DISTINCT] value [ORDER BY order_column [ASC\|DESC]] [SEPARATOR 'literal'])` and non-distinct `GROUP_CONCAT(value, value... ...)` over one descriptor-backed base table, where each value is a descriptor column or supported row-scalar expression and multiple values use per-row `CONCAT()` semantics before aggregation. The aggregate-local order key is a `NOT NULL` integer/`BIT`/`YEAR`/temporal descriptor column; aliases, source-qualified value/order columns, baseline `WHERE`, empty/all-`NULL` `NULL` results, and `@@group_concat_max_len` truncation warnings are covered for the supported subset. Multi-value `DISTINCT`, nullable/string/multiple order keys, binary result metadata, full grouping, joins, executable aggregate windows, and metadata threshold behavior remain limited |
| `GROUPING()` | ⚪ | Parser-admitted placeholder with explicit runtime rejection while `WITH ROLLUP` execution is unsupported; no super-aggregate row markers or executable `GROUPING()` behavior |
| `MAX()` | 🟡 | Limited mixed ungrouped `MAX([DISTINCT] expr)` over one descriptor-backed persistent base table with optional source alias, source-qualified operands, baseline `WHERE`, aliases, `LIMIT`, literals, and supported row-scalar arguments, plus limited grouped form over the current grouped source envelope; integer/`NULL` and nonbinary string result domains are covered for the documented envelope. Full grouping, aggregate ordering, binary string comparison semantics, and executable window forms remain limited |
| `MIN()` | 🟡 | Limited mixed ungrouped `MIN([DISTINCT] expr)` over one descriptor-backed persistent base table with optional source alias, source-qualified operands, baseline `WHERE`, aliases, `LIMIT`, literals, and supported row-scalar arguments, plus limited grouped form over the current grouped source envelope; integer/`NULL` and nonbinary string result domains are covered for the documented envelope. Full grouping, aggregate ordering, binary string comparison semantics, and executable window forms remain limited |
| `STD()` | 🟡 | Limited alias for `STDDEV_POP(expr)` in current mixed ungrouped, tableless, supported row-scalar, and grouped aggregate forms over integer descriptor values; empty/all-`NULL` inputs return `NULL`. No `DISTINCT`, string-to-double warnings, full grouping, or executable windows. See [baseline statistical aggregates](../specs/baseline-statistical-aggregates/specs.md) |
