# Cast functions

Explicit conversion functions.

| Function | Status | Notes |
| --- | --- | --- |
| `CAST()` | 🟡 | Limited no-source, `FROM DUAL`, `DO`, and single-table row-scalar `SELECT` `CAST(value AS BINARY)`, `CAST(value AS CHAR)`, `CAST(value AS DATE)`, `CAST(value AS SIGNED [INTEGER\|INT])`, and `CAST(value AS UNSIGNED [INTEGER\|INT])`; scalar contexts admit ordinary string, decimal integer, `TRUE`/`FALSE`, and `NULL` values, while row-scalar contexts additionally admit descriptor integer-family and nonbinary string-family columns plus supported folded session scalar values. `DATE` is a compatibility placeholder that currently uses character conversion values; source-backed row-scalar projections expose MySQL-shaped `DATE` result metadata. String-to-integer conversions produce MySQL-runtime-verified truncation/complement warnings for admitted string values; binary column storage is tracked separately under binary string types. No length-bearing binary or character casts, explicit character-set clauses, temporal targets beyond the `DATE` placeholder, decimal/float/JSON/spatial/other targets, binary string or `BIT` row operands, general expression operands, predicates, DML assignments, expression defaults, embedded-NUL scalar delivery, or full protocol-grade metadata |
| `CONVERT()` | 🟡 | Limited no-source, `FROM DUAL`, `DO`, and single-table row-scalar `SELECT` `CONVERT(value, BINARY)`, `CONVERT(value, CHAR)`, `CONVERT(value, DATE)`, `CONVERT(value, SIGNED [INTEGER\|INT])`, `CONVERT(value, UNSIGNED [INTEGER\|INT])`, `CONVERT(value USING BINARY)`, and `CONVERT(value USING utf8mb4\|utf8\|utf8mb3\|latin1)` including quoted charset names for the charset forms; scalar contexts admit ordinary string, decimal integer in the current scalar envelope, `TRUE`/`FALSE`, and `NULL` values, while row-scalar contexts additionally admit descriptor integer-family and nonbinary string-family columns plus supported folded session scalar values. `DATE` is a compatibility placeholder that currently uses character conversion values; source-backed row-scalar projections expose MySQL-shaped `DATE` result metadata. `utf8` and `utf8mb3` emit MySQL-compatible deprecation warnings, `latin1` is limited to ASCII scalar values, and result metadata is visible through result columns plus current `CHARSET()`, `COLLATION()`, `COERCIBILITY()`, and scalar postfix `COLLATE` surfaces. No length-bearing `BINARY(N)`/`CHAR(N)`, explicit character-set target clauses outside the listed `USING` names, temporal targets beyond the `DATE` placeholder, decimal/float/JSON/spatial/other targets, binary string or `BIT` row operands, general expression operands, predicates, DML assignments, expression defaults, general transcoding, embedded-NUL scalar delivery, or full protocol-grade metadata |
