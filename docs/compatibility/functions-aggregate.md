# Aggregate functions

Aggregate functions and grouping helpers.

The parser also admits common MySQL aggregate-window `OVER` syntax for the
current `COUNT(*)`, `COUNT(column)`, `COUNT(DISTINCT column)`, supported
row-scalar arguments for `SUM()` / `AVG()` / `MIN()` / `MAX()` / bitwise aggregates, and
`GROUP_CONCAT(...)`, plus JSON and statistical aggregate-window placeholders
such as `JSON_ARRAYAGG(...) OVER ...`, `JSON_OBJECTAGG(...) OVER ...`, and
`STDDEV_SAMP(...) OVER ...`. Execution of aggregate-window forms is explicitly
unsupported and returns a deterministic diagnostic. See
[parser aggregate window syntax](../specs/parser-aggregate-window-syntax/specs.md)
and [parser corpus aggregate/window surfaces](../specs/parser-corpus-aggregate-window-surfaces/specs.md)
and
[parser corpus JSON/statistical aggregate window surfaces](../specs/parser-corpus-json-stat-aggregate-window-surfaces/specs.md).

| Function | Status | Notes |

| `ANY_VALUE()` | 🟡 | Limited scalar and row-scalar transparent `ANY_VALUE(expr)` over already-supported scalar/row-scalar expressions, plus limited grouped `ANY_VALUE(column)` over descriptor-backed grouped sources where selected group columns are followed by aggregate-like results; grouped arguments are descriptor columns, representative values are arbitrary when a group contains different candidates, and selected aggregate aliases participate in the existing grouped `HAVING ... IS NULL` / `IS NOT NULL` and `ORDER BY alias [ASC\|DESC]` paths. No mixed ungrouped aggregate form, expression arguments in grouped use, `DISTINCT`, `*`, windows, DML/default/check/generated-column contexts, or deterministic representative-row selection |
| `AVG()` | 🟡 | Limited one-item `SELECT AVG(expr) [AS alias]` over one descriptor-backed persistent base table with optional source table alias, source-qualified operands, baseline `WHERE`, literal arguments, and supported row-scalar expression arguments, plus limited grouped form `SELECT group_column, AVG(expr) FROM source ... GROUP BY group_column` over one base table or the current two-source inner/cartesian/left-outer joined source envelope with optional selected-result `HAVING`; four-fractional-digit text results are produced while the intermediate signed-64 `SUM(expr)` stays in range. `AVG(DISTINCT expr)` and aggregate-window forms parse and reject deterministically. No executable `DISTINCT`, exact decimal widening beyond the signed-64 intermediate envelope, full grouping, aggregate ordering, or executable window forms |
| `BIT_AND()` | 🟡 | Limited one-item `SELECT BIT_AND(expr) [AS alias]` over one descriptor-backed persistent base table with optional source table alias, source-qualified operands, baseline `WHERE`, literal arguments, and supported row-scalar expression arguments, plus limited grouped form `SELECT group_column, BIT_AND(expr) FROM source ... GROUP BY group_column` over one base table or the current two-source inner/cartesian/left-outer joined source envelope; numeric unsigned-64 semantics with neutral all-ones output for empty/all-`NULL` input and unsigned decimal text results. No `DISTINCT`, binary-string evaluation, bitwise result `HAVING` predicates, full grouping, aggregate ordering, or executable window forms |

GROUP BY group_column` over one base table or the current two-source inner/cartesian/left-outer joined source envelope; numeric unsigned-64 semantics with neutral `0` output for empty/all-`NULL` input and unsigned decimal text results. | `COUNT()` | 🟡 | Limited `COUNT(*)` and `COUNT(integer/NULL/boolean literal)` in one-item `SELECT` with no source, `FROM DUAL`, or one descriptor-backed persistent base table, plus `COUNT(*)` over the current joined descriptor-source envelope with optional top-level `DISTINCT`, and limited `COUNT(column)` and `COUNT(DISTINCT column)` including parenthesized descriptor-column form `COUNT(DISTINCT(table.column))` over one descriptor-backed persistent base table; grouped form supports `SELECT group_column, COUNT(*)` and `SELECT group_column, COUNT(column)` over one descriptor-backed persistent base table or the current two-source inner/cartesian/left-outer joined source envelope with optional selected-result `HAVING`; optional select-item alias labels are supported, and optional source table alias, source-qualified column arguments, and baseline `WHERE` are supported for table-backed forms. | `COUNT(DISTINCT)` | 🟡 | Limited one-item `COUNT(DISTINCT column) [AS alias]` over one descriptor-backed persistent base table with optional source table alias, source-qualified column argument, parenthesized descriptor-column form such as `COUNT(DISTINCT(table.column))`, and baseline `WHERE`; integer/`NULL` descriptor columns only. The parser additionally admits multiple-expression, literal, and expression-shaped `COUNT(DISTINCT ...)` placeholders and rejects unsupported execution deterministically. No executable multiple expressions, expression arguments beyond parenthesized descriptor columns, executable literals, grouping, ordering, limiting, or executable window forms |
| `GROUP_CONCAT()` | 🟡 | Limited one-item `SELECT GROUP_CONCAT(column [ORDER BY order_column [ASC\|DESC]] [SEPARATOR 'literal']) [AS alias]` over one descriptor-backed persistent base table with optional source table alias, source-qualified value/order columns, and baseline `WHERE`, plus limited grouped form `SELECT group_column, GROUP_CONCAT(...) FROM table ... GROUP BY group_column` over one base table; integer and nonbinary string descriptor value columns only, aggregate-local order keys require `NOT NULL` integer/`BIT`/`YEAR`/temporal descriptor columns, empty/all-`NULL` input returns `NULL`, and output is byte-capped by session `@@group_concat_max_len` with MySQL-compatible truncation warnings for the supported subset. The parser additionally admits expression-shaped value arguments, `DISTINCT`, multi-expression value lists, and expression or multi-key aggregate-local `ORDER BY` lists, but those broader shapes are rejected by the current aggregate planner. No executable `DISTINCT`, executable expression arguments, executable multiple value arguments, executable nullable or string order keys, executable multiple order keys, binary result metadata, full grouping, joins, executable aggregate windows, or metadata threshold behavior |
| `GROUPING()` | ⚪ | Parser-admitted placeholder with explicit runtime rejection while `WITH ROLLUP` execution is unsupported; no super-aggregate row markers or executable `GROUPING()` behavior |

GROUP BY group_column` over one base table or the current two-source inner/cartesian/left-outer joined source envelope with optional selected-result `HAVING`; integer/`NULL` and nonbinary string result domains are covered for the documented envelope.
