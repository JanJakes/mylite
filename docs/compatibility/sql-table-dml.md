# SQL table DML

Table-shaped data modification, import, replace, and direct table access
statements.

| Feature | Status | Notes |
| --- | --- | --- |
| `DELETE` (single-table) | 🟡 | Limited persistent base-table `DELETE FROM table` with optional baseline integer/`NULL` `WHERE` predicate boolean expression, including keyword `NOT`, limited `BETWEEN` range predicates, and limited `IN` membership predicates, one unqualified descriptor `ORDER BY` column, optional `ASC`/`DESC`, exact affected rows, and `LIMIT row_count` using unsigned decimal literals in signed 64-bit range; no aliases, partitions, modifiers, joined deletes, `USING`, full ordering, offset forms, triggers, cascades, foreign keys, or privilege semantics |
| `DELETE` (multi-table) | ❌ | Multi-table forms and affected rows |
| `HANDLER` | ❌ | HANDLER OPEN, READ, and CLOSE cursor-like table access |
| `INSERT ... VALUES` | 🟡 | Limited single- and multi-row `INSERT [LOW_PRIORITY \| HIGH_PRIORITY \| DELAYED] [IGNORE] [INTO] table_name ... VALUES ...` into persistent base tables with optional unqualified column lists, integer/`NULL`/`TRUE`/`FALSE` values, descriptor-driven assignment, omitted columns filled from descriptor integer defaults or effective `NULL` defaults, strict range/nullability/no-default diagnostics, affected rows, all-or-nothing statement behavior, no-op `LOW_PRIORITY` / `HIGH_PRIORITY`, warning-producing deprecated `DELAYED`, and limited `IGNORE` warning demotion for omitted no-explicit-default columns, explicit `NULL` into numeric `NOT NULL`, and integer range clipping; no-column-list inserts target visible descriptor columns only, while explicit column lists may name invisible columns; nullable dropped-default columns warn and store `NULL`, numeric `NOT NULL` no-default columns warn and store `0`; no DML `DEFAULT` keyword values, keys, insert ids, duplicate-key discard, `ON DUPLICATE KEY UPDATE`, or `SELECT` form |
| `INSERT ... SET` | 🟡 | Limited one-row `INSERT [LOW_PRIORITY \| HIGH_PRIORITY \| DELAYED] [IGNORE] [INTO] table_name SET column_name = value[, ...]` into persistent base tables with unqualified assignment columns, supported decimal integer/`NULL`/`TRUE`/`FALSE` values, descriptor-driven assignment including invisible columns when explicitly named, omitted columns filled from descriptor integer defaults or effective `NULL` defaults, strict required-column/range/nullability diagnostics, one affected row, all-or-nothing statement behavior, no-op `LOW_PRIORITY` / `HIGH_PRIORITY`, warning-producing deprecated `DELAYED`, and limited `IGNORE` warning demotion for omitted no-explicit-default columns, explicit `NULL` into numeric `NOT NULL`, and integer range clipping; nullable dropped-default columns warn and store `NULL`, numeric `NOT NULL` no-default columns warn and store `0`; no table-qualified assignment targets, expression assignments, DML `DEFAULT` keyword values, generated values, aliases, partitions, insert ids, duplicate-key discard, `ON DUPLICATE KEY UPDATE`, or `SELECT` form |
| `INSERT ... SELECT` | 🟡 | Limited descriptor-backed `INSERT [LOW_PRIORITY \| HIGH_PRIORITY \| DELAYED] [INTO] target [(column_name[, ...])] SELECT ... FROM source` for persistent base tables, reusing the existing single-table source `SELECT` subset with optional table alias, `WHERE`, one-column `ORDER BY`, and `LIMIT`; target column lists are descriptor-driven, omitted targets receive descriptor integer defaults or effective nullable `NULL` only for rows actually inserted, source/target `*` and omitted target lists use visible columns, explicit columns may name invisible columns, selected integer/`NULL` values are validated against target descriptors, `LOW_PRIORITY` / `HIGH_PRIORITY` are no-ops, and `DELAYED` records MySQL's deprecated-delayed warning; no `IGNORE`, partitions, `ON DUPLICATE KEY UPDATE`, `TABLE`, row constructors, joins, CTEs, literal/expression projection sources, keys, auto-increment, triggers, generated columns, warning demotion, or general expression conversion |
| `INSERT ... ON DUPLICATE KEY UPDATE` | ❌ | Conflict handling and warnings |
| `INSERT IGNORE` | 🟡 | Limited `INSERT IGNORE ... VALUES` and `INSERT IGNORE ... SET` warning demotion for descriptor integer/`NULL` inputs: omitted no-explicit-default columns warn and store `0` for numeric `NOT NULL` or `NULL` for nullable dropped-default columns, explicit `NULL` into numeric `NOT NULL` stores `0` with warnings, out-of-range integer values clip to the supported descriptor range with warnings, and non-ignorable syntax/name/shape errors remain errors; no `INSERT IGNORE ... SELECT`, duplicate-key discard, partitions, generated values, string/decimal/float/hex/bit conversion, general expression conversion, or full non-strict mode behavior |
| `INSERT DELAYED` | 🟡 | Limited modifier support on currently supported `INSERT ... VALUES`, `INSERT ... SET`, and descriptor-backed `INSERT ... SELECT` forms; executes as ordinary `INSERT` and records warning `3005`; `VALUES` and `SET` may combine `DELAYED IGNORE` with delayed warning before adjustment warnings; no delayed queues, background writes, storage scheduling, or `INSERT IGNORE ... SELECT` |
| `INSERT LOW_PRIORITY` / `HIGH_PRIORITY` | 🟡 | Limited no-op priority modifier support on currently supported `INSERT ... VALUES`, `INSERT ... SET`, and descriptor-backed `INSERT ... SELECT` forms; `VALUES` and `SET` may combine one priority modifier before `IGNORE`; no table-lock scheduling semantics, multiple modifiers, or `INSERT IGNORE ... SELECT` |
| `LOAD DATA INFILE` | ❌ | Server-side import syntax |
| `LOAD DATA LOCAL INFILE` | ❌ | LOCAL INFILE flow and security |
| `LOAD XML INFILE` | ❌ | XML import syntax |
| `LOAD XML LOCAL INFILE` | ❌ | Client-side XML import request behavior diagnostics |
| `REPLACE ... VALUES` | 🟡 | Limited no-key-descriptor `REPLACE [LOW_PRIORITY \| DELAYED] [INTO] table_name [(column_name[, ...])] VALUES (value[, ...])[, ...]` insert-equivalent path for persistent base tables with integer/`NULL`/`TRUE`/`FALSE` values, descriptor column resolution including explicitly named invisible columns, omitted-column descriptor default filling, strict range/nullability/no-default diagnostics, affected rows equal to inserted rows, all-or-nothing statement behavior, no-op `LOW_PRIORITY`, and warning-producing deprecated `DELAYED`; duplicate-key delete-insert semantics await primary/unique key descriptors, and there is no `VALUE` synonym, row constructors, partitions, generated values, warning demotion, or insert ids |
| `REPLACE ... SET` | 🟡 | Limited no-key-descriptor one-row `REPLACE [LOW_PRIORITY \| DELAYED] [INTO] table_name SET column_name = value[, ...]` insert-equivalent path for persistent base tables with unqualified descriptor assignment targets, integer/`NULL`/`TRUE`/`FALSE` values, omitted-column descriptor default filling, strict range/nullability/no-default diagnostics, one affected row, all-or-nothing statement behavior, no-op `LOW_PRIORITY`, and warning-producing deprecated `DELAYED`; duplicate-key delete-insert semantics await primary/unique key descriptors, and there are no partitions, qualified assignment targets, expression/default assignments, `VALUES`, or `SELECT` forms |
| `REPLACE ... SELECT` | 🟡 | Limited no-key-descriptor `REPLACE [LOW_PRIORITY \| DELAYED] [INTO] target [(column_name[, ...])] SELECT ... FROM source` insert-equivalent path for persistent base tables, reusing the existing single-table source `SELECT` subset with optional table alias, `WHERE`, one-column `ORDER BY`, and `LIMIT`; target column lists are descriptor-driven, omitted targets receive descriptor integer defaults or effective nullable `NULL` only for rows actually inserted, source/target `*` and omitted target lists use visible columns, explicit columns may name invisible columns, and selected integer/`NULL` values are validated against target descriptors; duplicate-key delete-insert semantics await primary/unique key descriptors, and there are no partitions, `TABLE`, joins, CTEs, literal/expression projection sources, generated values, warning demotion, or insert ids |
| `REPLACE LOW_PRIORITY` / `DELAYED` | 🟡 | Limited modifier support on currently supported no-key `REPLACE` forms: `LOW_PRIORITY` is accepted as a no-op and `DELAYED` executes as ordinary `REPLACE` with warning `3005`; no multiple modifiers, `HIGH_PRIORITY`, delayed queues, storage scheduling changes, or duplicate-key replacement semantics |
| `UPDATE` (single-table) | 🟡 | Limited persistent base-table `UPDATE table_name SET column_name = value` with one unqualified assignment column, supported decimal integer/`NULL`/`TRUE`/`FALSE` assignment values, optional baseline `WHERE` predicate boolean expression including keyword `NOT`, limited `BETWEEN` range predicates, and limited `IN` membership predicates, optional one-column `ORDER BY` with `ASC`/`DESC`, and optional `LIMIT row_count` using unsigned decimal literals in signed 64-bit range; assignment, predicate, and ordering columns resolve through descriptors and may explicitly name invisible columns; affected rows report changed rows; no aliases, table-qualified assignment targets, multiple assignments, expression assignments, defaults, partitions, modifiers, joined updates, multi-table updates, table-qualified/order expression/ordinal/multiple-key ordering, offset forms, triggers, cascades, foreign keys, generated columns, or privilege semantics |
| `UPDATE` (multi-table) | ❌ | Joined update semantics |
| SQL safe updates variable | 🟡 | Limited scalar `@@sql_safe_updates` reads report fixed disabled value `0`; no mutable safe-updates state, `sql_select_limit`, `max_join_size`, key-aware DML checks, or changed `UPDATE`/`DELETE` behavior |
| SQL warnings variable | 🟡 | Limited scalar `@@sql_warnings` reads report fixed disabled value `0`; limited `INSERT IGNORE ... VALUES` / `SET` adjustment warnings are still recorded in diagnostics like MySQL; no mutable warning-reporting state, broader warning-producing insert conversions, strict warning demotion beyond the limited `INSERT IGNORE` subset, or single-row insert information strings |
