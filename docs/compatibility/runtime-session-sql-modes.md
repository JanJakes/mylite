# Runtime session state and SQL modes

Session-local MySQL state and SQL modes that affect parsing, coercion, diagnostics, and runtime behavior.

## Session and runtime state

| Feature | Status | Notes |
| --- | --- | --- |
| Default schema | ❌ | Current schema state |
| SQL mode scalar value | 🟡 | Limited session-local `@@sql_mode`, `@@SESSION.sql_mode`, `@@LOCAL.sql_mode`, `SET sql_mode`, and `SHOW VARIABLES` support with fixed MySQL 8.4.9 default/global readback, canonical assigned mode strings, and behavioral effects for `ANSI_QUOTES`, `NO_BACKSLASH_ESCAPES`, `NO_AUTO_VALUE_ON_ZERO`, `NO_ENGINE_SUBSTITUTION` on current `CREATE TABLE` / `CREATE TEMPORARY TABLE` engine validation, `REAL_AS_FLOAT`, limited `PIPES_AS_CONCAT` `||` scalar concatenation, plus the current `DATE` / `DATETIME` / `TIMESTAMP` zero-temporal subset for `STRICT_TRANS_TABLES`, `STRICT_ALL_TABLES`, `NO_ZERO_DATE`, `NO_ZERO_IN_DATE`, and `ALLOW_INVALID_DATES` including supported ALTER default changes, limited ordinary non-strict `INSERT` / `REPLACE` omitted non-`AUTO_INCREMENT`/default plus matched `UPDATE` `NULL`/`DEFAULT` DML adjustment, limited `UPDATE IGNORE` assignment conversion demotion even when strict mode is active, limited descriptor-backed `INSERT ... SELECT` omitted-target, selected-`NULL`, selected-integer-range, and selected-`CHAR`/`VARCHAR` truncation adjustment, and limited duplicate-key update assignment adjustment for no-default `DEFAULT`, character truncation, and multi-row literal `NULL` to integer `NOT NULL` targets when neither strict mode is active; no mutable global state, predicate-level `PIPES_AS_CONCAT`, full strict/non-strict conversion coverage, or broader mode behavior |
| Connection character set state | 🟡 | Fixed `utf8mb4` / `utf8mb4_0900_ai_ci` baseline with limited scalar reads and no-op `SET NAMES` / `SET CHARACTER SET` forms that preserve that baseline; no mutable conversion state |
| Time zone state | 🟡 | Limited fixed embedded `system_time_zone = UTC`, fixed global `time_zone = SYSTEM`, and session-local `SET time_zone` subset for `DEFAULT`, `SYSTEM`, `UTC`, and signed UTC offsets. Current date/time/timestamp materialization uses the session offset; `mysql.time_zone*` tables are metadata-only empty placeholders with no loaded named-zone rows, mutable global time zone, named-zone conversion beyond `UTC`, leap-second handling, or TIMESTAMP row storage/retrieval conversion |
| Autocommit state | 🟡 | Limited scalar `@@autocommit` reads and fixed no-op `SET autocommit = 1` forms report/preserve visible value `1`; explicit user transactions are supported through `START TRANSACTION` / `BEGIN` while visible autocommit remains enabled; no mutable `SET autocommit = 0`, protocol status flags, or full autocommit side effects |
| Last insert id | 🟡 | Limited connection-local unsigned 64-bit state for the current persistent and session-temporary auto-increment insert subset plus literal `LAST_INSERT_ID(expr)` scalar/`DO` calls; generated auto-increment statements expose the first generated id through MyLite result metadata and mysqli `insert_id`; manual values are not persisted and are overwritten by later successful generated inserts; no table-backed expression evaluation, wire-protocol insert-id packets, mixed-mode allocation parity, or stored-program behavior |
| Affected rows | ❌ | Found/changed row counts |
| Warnings and diagnostics | ❌ | Warnings, errors, diagnostics area |
| Prepared statement registry | 🟡 | Limited handle-local SQL-level prepared statement registry for `PREPARE`, `EXECUTE`, and `DEALLOCATE PREPARE` / `DROP PREPARE`; entries are nonpersistent, case-insensitive by name, and invisible to metadata tables. No binary protocol registry, marker metadata, status counters, performance-schema rows, or `max_prepared_stmt_count` enforcement |
| Temporary table namespace | 🟡 | Limited per-session temporary table descriptors for explicit `CREATE TEMPORARY TABLE` / `DROP TEMPORARY TABLE`, session-local auto-increment counters for the current indexed subset, same-schema shadowing for current descriptor-driven DML and selected SHOW statements, and close-time cleanup; no cross-handle visibility, temporary DDL inside active user transactions, temporary CTAS/ALTER/RENAME/TRUNCATE, or privilege state |
| Role and privilege state | 🟡 | Fixed embedded `root@%` identity with no active role, no account store, and limited synthetic `INFORMATION_SCHEMA.USER_PRIVILEGES` readback for global privileges; no mutable roles, grant descriptors, grant/revoke DDL, lower-level privilege rows, privilege filtering, or enforcement |
| Locks | ❌ | Named, table, metadata, backup locks |

## SQL modes

| SQL mode | Status | Notes |
| --- | --- | --- |
| `ALLOW_INVALID_DATES` | 🟡 | Accepted and reflected in session `@@sql_mode`; limited effect for canonical and admitted `T`-separator `DATE` / `DATETIME` row values, defaults, compatible descriptor copies, and predicates whose year is inside MyLite's current `1000..9999` range, month is `1..12`, and day is `1..31`; no effect for `TIMESTAMP`, numeric-offset or trailing-`Z` relaxed temporal strings, pre-1000 non-full-zero dates, functions, or general conversion |
| `ANSI` | 🟡 | Accepted and reflected as a composite session mode; its `ANSI_QUOTES`, `REAL_AS_FLOAT`, and limited `PIPES_AS_CONCAT` effects are currently implemented |
| `ANSI_QUOTES` | 🟡 | Limited lexer effect: double-quoted tokens in later statements are parsed as quoted identifiers rather than string literals |
| `ERROR_FOR_DIVISION_BY_ZERO` | 🟡 | Accepted and reflected in session `@@sql_mode` and appears in the default/global value; division-by-zero and strict-mode effects remain unsupported |
| `HIGH_NOT_PRECEDENCE` | 🟡 | Accepted and reflected in session `@@sql_mode`; operator-precedence effects remain unsupported |
| `IGNORE_SPACE` | 🟡 | Accepted and reflected in session `@@sql_mode`; limited function-name parsing effect for the currently admitted built-in scalar-function slices; no full reserved-function-name parsing parity |
| `NO_AUTO_VALUE_ON_ZERO` | 🟡 | Limited DML effect: explicit `0` inserted into current descriptor-owned `AUTO_INCREMENT` paths stores zero instead of being replaced by a generated value; exact InnoDB-style counter reservation gaps after all prior insert patterns remain outside the current slice |
| `NO_BACKSLASH_ESCAPES` | 🟡 | Limited lexer and string-decoding effect for later admitted string literals; broader string and pattern semantics are still unsupported |
| `NO_DIR_IN_CREATE` | 🟡 | Accepted and reflected in session `@@sql_mode`; directory-option effects remain unsupported |
| `NO_ENGINE_SUBSTITUTION` | 🟡 | Accepted and reflected in session `@@sql_mode` and appears in the default/global value; when active, explicit non-InnoDB or empty `ENGINE` names in current `CREATE TABLE` / `CREATE TEMPORARY TABLE` forms are rejected with `1286`; when absent, they are substituted to MyLite's InnoDB-backed table storage with `1286` and `1266` warnings. No broader engine metadata, `ALTER TABLE ... ENGINE`, default-engine mutation, or real alternate engine behavior |
| `NO_UNSIGNED_SUBTRACTION` | 🟡 | Accepted and reflected in session `@@sql_mode`; arithmetic type effects remain unsupported |
| `NO_ZERO_DATE` | 🟡 | Accepted and reflected in session `@@sql_mode` and appears in the default/global value; limited effect for full-zero canonical and admitted relaxed `DATE`, `DATETIME`, and `TIMESTAMP` row values, defaults, compatible descriptor copies, and predicates, including strict errors and nonstrict warning-plus-zero behavior for the supported subset; supported metadata-changing ALTER default paths revalidate existing full-zero temporal descriptor defaults and report MySQL-compatible cumulative warning counts; no relaxed temporal strings outside the documented storage, default, and predicate slices, pre-1000 non-full-zero dates, functions, or general conversion |
| `NO_ZERO_IN_DATE` | 🟡 | Accepted and reflected in session `@@sql_mode` and appears in the default/global value; limited effect for canonical and admitted relaxed partial-zero `DATE` and `DATETIME` row values, defaults, compatible descriptor copies, and predicates inside MyLite's current `1000..9999` year envelope, including strict errors and nonstrict warning-plus-full-zero behavior; supported ALTER default paths adjust partial-zero `DATE` / `DATETIME` defaults with MySQL-compatible warnings; no effect for `TIMESTAMP`, relaxed temporal strings outside the documented storage, default, and predicate slices, pre-1000 non-full-zero dates, functions, or general conversion |
| `ONLY_FULL_GROUP_BY` | 🟡 | Accepted and reflected in session `@@sql_mode` and appears in the default/global value; documented grouped-query validation slices currently apply directly for grouped projection and limited complete-primary-key functional dependence, while grouped descriptor-column `ORDER BY` validation is conditional on this mode; broader MySQL `ONLY_FULL_GROUP_BY` semantics remain unsupported |
| `PAD_CHAR_TO_FULL_LENGTH` | 🟡 | Accepted and reflected in session `@@sql_mode` and emits the verified MySQL deprecation warning; `CHAR` readback padding effects remain unsupported |
| `PIPES_AS_CONCAT` | 🟡 | Accepted and reflected in session `@@sql_mode`; limited mode-sensitive `||` string concatenation is supported for no-source/`DUAL` scalar projection, `DO`, and current single-table row-scalar `SELECT` projection over the existing `CONCAT()` operand envelope; predicates, DML assignments, ordering/grouping expressions, scalar logical `||` outside this mode, and general expression metadata remain unsupported |
| `REAL_AS_FLOAT` | 🟡 | Limited DDL effect: later `REAL` column definitions map to MyLite's `FLOAT` descriptor subset instead of `DOUBLE` |
| `STRICT_ALL_TABLES` | 🟡 | Accepted and reflected in session `@@sql_mode`; limited strict conversion effect for the current zero-temporal and trailing-`Z` / `z` `DATE` / `DATETIME` / `TIMESTAMP` subset when combined with `NO_ZERO_DATE`, `NO_ZERO_IN_DATE`, or invalid temporal inputs, and for ordinary DML missing-default / matched-update `NULL` and `DEFAULT` errors when active; broader strict conversion and warning escalation effects remain unsupported |
| `STRICT_TRANS_TABLES` | 🟡 | Accepted and reflected in session `@@sql_mode` and appears in the default/global value; limited strict conversion effect for the current zero-temporal and trailing-`Z` / `z` `DATE` / `DATETIME` / `TIMESTAMP` subset when combined with `NO_ZERO_DATE`, `NO_ZERO_IN_DATE`, or invalid temporal inputs, and for ordinary DML missing-default / matched-update `NULL` and `DEFAULT` errors when active; broader strict conversion and warning escalation effects remain unsupported |
| `TIME_TRUNCATE_FRACTIONAL` | 🟡 | Accepted and reflected in session `@@sql_mode`; fractional-time truncation effects remain unsupported |
| `TRADITIONAL` | 🟡 | Accepted and reflected as a composite session mode; only the currently implemented constituent effects are observable, including the limited zero-temporal strict behavior |
