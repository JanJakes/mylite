# Error, warning, and result semantics

| Feature | Status | Notes |
| --- | --- | --- |
| Error code catalog | 🟡 | Limited MySQL-compatible numeric error codes, SQLSTATE values, and message fragments for currently emitted baseline parse, system-variable, DDL, DML, type-conversion, metadata, and diagnostics conditions, including top-level multi-statement input rejected with a MySQL-shaped syntax diagnostic at the second statement; no complete MySQL server error catalog, stored-program diagnostics, privilege-sensitive errors, or wire-protocol error-packet parity. See [baseline diagnostics codes and order](../specs/baseline-diagnostics-code-order/specs.md) |
| Warning code catalog | 🟡 | Limited MySQL-compatible numeric warning/note codes, SQLSTATE values, and FIFO `SHOW WARNINGS` order for current warning and note producers, including deprecation, truncation, and missing-object diagnostics; no complete warning catalog, diagnostics stacks, or broader warning producer coverage. See [baseline diagnostics codes and order](../specs/baseline-diagnostics-code-order/specs.md) |
| Diagnostics area | 🟡 | Limited previous-statement diagnostics snapshot for `SHOW WARNINGS`, `SHOW ERRORS`, `SHOW COUNT(*) WARNINGS`, `SHOW COUNT(*) ERRORS`, and scalar `@@warning_count` / `@@error_count`; supports current warning/note/error records, `@@max_error_count` retained-row capping with total warning-count preservation, and `sql_notes=0` suppression for current note producers. Missing-schema `DROP DATABASE IF EXISTS` exposes a statement warning count but intentionally stores no diagnostics row; `GET DIAGNOSTICS` is parsed only to return unsupported utility diagnostics; no diagnostics stacks, stored-program handlers, or broader warning producer coverage |
| Native and PHP diagnostic ownership | ✅ | Native statement and direct-result snapshots preserve total versus retained warning counts and caller-owned indexed copies; PDO keeps connection and statement `errorInfo()` records independent; mysqli exposes copied direct and prepared FIFO warning chains whose returned objects survive later work and close. See [statement diagnostics and warning snapshots](../specs/statement-diagnostics-warning-snapshots/specs.md) |
| mysqli commands out of sync | ✅ | Direct pending results and direct or prepared unbuffered owners reject disallowed commands with error `2014`, SQLSTATE `HY000`, and the MySQL 8.4.9 message without consuming the active result. PHP 8.3 retained-error reporting and PHP 8.4 direct-fetch behavior are both matched. Buffering, EOF, free, reset, re-execution, close, and destruction release ownership as documented. See [mysqli pending-result state machine](../specs/mysqli-pending-result-state-machine/specs.md) |
| SQL notes variable | ✅ | MySQL-runtime-verified scalar reads, `SHOW VARIABLES`, Boolean session `SET` forms, fixed global readback, and `sql_notes=0` suppression for current note producers; disabled notes do not increment `@@warning_count` or appear in `SHOW WARNINGS`. No mutable shared global state, startup/persisted value, Performance Schema variable table, diagnostics stack, or complete note-producing surface |
| SQL warnings variable | ✅ | `@@sql_warnings` supports session readback, SET/SHOW forms, scoped reads, and expression reads; limited non-strict and `INSERT IGNORE` string truncation plus `INSERT IGNORE` adjustment, duplicate, supported foreign-key warnings, and limited `UPDATE IGNORE` assignment adjustment warnings are recorded in diagnostics like MySQL for documented DML subsets; no global mutation, persisted state, broader warning-producing DML conversions, single-row insert information strings, or protocol status changes |
| Strict-mode errors | 🟡 | Limited strict-mode escalation for descriptor-backed DML conversion paths: default `STRICT_TRANS_TABLES` preserves errors for omitted no-default `NOT NULL` values, no-default DML `DEFAULT`, supported explicit `NULL` into `NOT NULL`, `CHAR`/`VARCHAR` nonspace overflow, numeric conversion/range failures, and zero-temporal mode combinations documented by the non-strict, DML conversion, and zero-temporal specs; full MySQL strict behavior for arbitrary expressions, generated columns, triggers, stored programs, `LOAD DATA`, protocol info strings, and every warning producer remains incomplete |
| IGNORE warning demotion | 🟡 | Limited `INSERT IGNORE ... VALUES` / `SET` demotion for descriptor integer, decimal, approximate, string, binary string, `BIT`, `YEAR`, temporal, `NULL`, and `DEFAULT` row inputs, plus limited table-backed `INSERT IGNORE ... SELECT` demotion, including supported `AUTO_INCREMENT` targets, for omitted targets, selected `NULL`, selected integer range clipping, selected `CHAR`/`VARCHAR` truncation, duplicate-key rows, and supported missing-parent rows: explicit `NULL` into supported `NOT NULL` descriptors, omitted no-explicit-default columns, explicit `DEFAULT` for no-default columns, out-of-range descriptor integer/decimal/time/year inputs, invalid year or temporal inputs, overlength `CHAR`/`VARCHAR` strings, overlength binary strings, over-width `BIT` inputs, duplicate-key rows, and missing-parent rows for supported foreign-key child descriptors become warnings with adjusted or skipped values; omitted or explicit-`DEFAULT` numeric `NOT NULL` no-default columns store `0`, `YEAR NOT NULL` stores `0000`, `DATE NOT NULL` stores `0000-00-00`, `TIME NOT NULL` stores `00:00:00`, `DATETIME NOT NULL` or `TIMESTAMP NOT NULL` stores `0000-00-00 00:00:00`, string `NOT NULL` stores empty string, binary string and `BIT NOT NULL` store their current implicit values, nullable dropped-default columns store `NULL`, and missing-parent foreign-key child rows are skipped; out-of-range `TIME` values clip to `-838:59:59` or `838:59:59`. Limited single-table `UPDATE IGNORE` demotes the currently supported assignment conversion failures for matched rows, including `NULL` into `NOT NULL`, no-default `DEFAULT`, string truncation, integer range clipping, and invalid temporal values, but rejects key or auto-increment assignments instead of emulating duplicate-key row skipping; no broader type conversion, row-scalar or compound-source `INSERT IGNORE ... SELECT`, exact InnoDB bulk auto-increment reserve-gap emulation after `INSERT ... SELECT`, duplicate-key skip behavior for `UPDATE IGNORE`, `DELETE IGNORE`, or `LOAD DATA IGNORE` demotion |
| Metadata flags | 🟡 | Limited public `mylite_result` metadata and flag accessors for descriptor-backed single-table `SELECT` columns plus documented scalar and row-scalar expression results, including labels, schema/table/origin names where applicable, MySQL field type IDs, display lengths, charset/collation IDs, decimals, nullability, enum descriptors, and descriptor/index-derived flag bits including the public enum bit; no wire protocol packets, prepared-statement metadata, optional metadata negotiation, `max_length`, privilege-sensitive metadata, joined/grouped/SHOW/INFORMATION_SCHEMA metadata parity, or complete arbitrary expression metadata |
| Result ordering guarantees | ❌ | Required ordering guarantees |
| Floating-point edge cases | ❌ | NaN, Inf, rounding, comparison |
| Temporal edge cases | ❌ | Zero dates, DST, fractional seconds |
| JSON edge cases | ❌ | Keys, ordering, paths, partial updates |
| Spatial edge cases | ❌ | SRID, invalid geometry, units |
| Privilege-sensitive metadata | ❌ | Grant-sensitive metadata visibility |
