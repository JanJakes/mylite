# SQL indexes and constraints

Standalone index statements plus index, key, constraint, foreign-key, and check DDL details.

## Statement surface

| Feature | Status | Notes |
| --- | --- | --- |
| `CREATE INDEX` | 🟡 | Limited standalone `CREATE INDEX index_name ON table_name (key_part[, ...])` for persistent base tables with unqualified descriptor columns, including nonunique composite indexes and nonunique string prefix parts on `CHAR`, `VARCHAR`, and bare `TEXT` family descriptors within current type-family and 3072-byte key-length envelopes. `CREATE UNIQUE INDEX` supports one or more full existing supported descriptor columns, plus string prefix keys including composite prefix key parts on `CHAR`, `VARCHAR`, and bare `TEXT` family descriptors. Supported key parts may specify `ASC` or `DESC`; omitted direction is ascending. Creates descriptor-owned index metadata plus one generated SQLite index, reports zero affected rows/warnings, validates existing duplicate rows for unique indexes, and updates descriptor-driven `SHOW`, `CREATE TABLE ... LIKE`, limited `INFORMATION_SCHEMA`, DML duplicate checks, and `ALTER TABLE ... DROP INDEX\|KEY` / standalone `DROP INDEX`. No omitted names, `IF NOT EXISTS`, fulltext/spatial indexes, primary-key creation, functional/table-qualified key parts, options, comments, visibility, algorithms, locks, temporary tables, views, or optimizer guarantees |
| `DROP INDEX` | 🟡 | Limited standalone `DROP INDEX index_name ON table_name` for descriptor-owned unique, nonunique secondary, and metadata-only full-text indexes on persistent base tables; deletes descriptors and the generated SQLite index when one exists, preserves rows, columns, primary keys, other supported secondary indexes, and allowed auto-increment descriptors, reports zero affected rows/warnings, rejects drops of indexes used by supported foreign-key descriptors, and updates descriptor-driven `SHOW`, `CREATE TABLE ... LIKE`, limited `INFORMATION_SCHEMA`, and DML behavior. No standalone `DROP KEY`, `IF EXISTS`, primary-key drops through ``DROP INDEX `PRIMARY` ON ...``, algorithms, locks, temporary tables, views, cascades, triggers, or optimizer guarantees |
| `CACHE INDEX` | ❌ | MyISAM key cache assignment syntax |
| `LOAD INDEX INTO CACHE` | ❌ | MyISAM index preload syntax |

## Index and constraint details

| Feature | Status | Notes |
| --- | --- | --- |
| Primary keys | 🟡 | Limited descriptor-owned primary keys declared in `CREATE TABLE` or added later with `ALTER TABLE ... ADD PRIMARY KEY (column[, ...])`, and keys removed with `ALTER TABLE ... DROP PRIMARY KEY`. Supported key parts are integer-family descriptors and ASCII-valued `CHAR(1..255)` / `VARCHAR(1..255)` descriptors, including table-level composite integer, string, and mixed keys, with optional `ASC` / `DESC` direction metadata on table-level and alter-added parts. Added keys validate existing rows for `NULL`, duplicate key tuples, supported ASCII string-key values, and the 3072-byte aggregate key-length envelope, make every key-part descriptor column `NOT NULL`, preserve supported defaults and secondary indexes, and create a generated SQLite unique index with the MyLite `utf8mb4_0900_ai_ci` ASCII collation annotation for string key parts. Dropped keys remove the descriptor rows and generated physical index, preserve rows, column descriptors, and supported secondary indexes, leave former key columns `NOT NULL`, report the current table row count, reject drops when the key is referenced by a supported foreign key, and keep an auto-increment column only if a supported secondary index still indexes it. Existing DML enforces duplicate keys for current `INSERT ... VALUES` / `INSERT ... SET`, `INSERT IGNORE`, and single-assignment `UPDATE`; supported integer primary keys may serve as one-column or composite FK parent keys; `CREATE TABLE ... LIKE`, `SHOW COLUMNS` / `SHOW INDEX` / `SHOW CREATE TABLE`, and limited `INFORMATION_SCHEMA.COLUMNS.COLUMN_KEY`, `INFORMATION_SCHEMA.STATISTICS`, `INFORMATION_SCHEMA.TABLE_CONSTRAINTS`, and `INFORMATION_SCHEMA.KEY_COLUMN_USAGE` metadata observe the descriptor. No primary prefix parts, non-ASCII string key values, named primary-key constraints, auto-increment conversion, or optimizer/index-use guarantees |
| Unique indexes | 🟡 | Limited descriptor-owned unique indexes declared inside `CREATE TABLE` with inline `UNIQUE` / `UNIQUE KEY`, table-level `UNIQUE [KEY\|INDEX] [name] (column[, ...])`, named table-level `CONSTRAINT name UNIQUE [KEY\|INDEX] (key_part[, ...])` forms that store the visible unique-index name in the existing secondary-index descriptor, standalone `CREATE UNIQUE INDEX index_name ON table_name (column_name[, ...])`, or single-action `ALTER TABLE table_name ADD UNIQUE [INDEX\|KEY] [name] (column_name[, ...])` on integer-family, exact `DECIMAL`, canonical `YEAR`, canonical `DATE`, canonical `TIME`, canonical `DATETIME`, canonical `TIMESTAMP`, and ASCII-valued `CHAR(1..255)` / `VARCHAR(1..255)` full descriptor columns; string prefix unique indexes including composite prefix key parts are supported on `CHAR`, `VARCHAR`, and bare `TEXT` family descriptors. Supported table-level, named table-level, alter-added, and standalone key parts may specify `ASC` or `DESC`; omitted direction is ascending. The descriptor is backed by a generated SQLite unique index, using the MyLite `utf8mb4_0900_ai_ci` ASCII collation annotation for string key parts and prefix expressions, cloned by `CREATE TABLE ... LIKE`, omitted by `CREATE TABLE ... SELECT`, removable with limited `ALTER TABLE ... DROP INDEX\|KEY` or standalone `DROP INDEX`, rendered in `SHOW COLUMNS`, `SHOW CREATE TABLE`, `SHOW INDEX`, and limited `INFORMATION_SCHEMA.STATISTICS`, `INFORMATION_SCHEMA.TABLE_CONSTRAINTS`, and `INFORMATION_SCHEMA.KEY_COLUMN_USAGE`, and enforced for existing-row validation, `INSERT ... VALUES`, `INSERT ... SET`, `INSERT IGNORE ... VALUES` / `SET`, the existing one-key `INSERT ... ON DUPLICATE KEY UPDATE` subset for single-column keys, and single-assignment `UPDATE`. Multiple `NULL` values are allowed. No `ALTER TABLE ... ADD CONSTRAINT UNIQUE`, `ALTER TABLE ... RENAME UNIQUE`, non-ASCII string key values, primary prefix indexes, functional key parts, separate unique-constraint descriptors, redundant-index warnings, visibility toggles, comments, parser options, or optimizer-use guarantees |
| Nonunique indexes | 🟡 | Limited table-level `KEY` / `INDEX [name] (key_part[, ...])` definitions inside `CREATE TABLE` plus limited single-action `ALTER TABLE table_name ADD INDEX\|KEY [name] (key_part[, ...])`, standalone `CREATE INDEX index_name ON table_name (key_part[, ...])`, `ALTER TABLE table_name DROP INDEX\|KEY index_name`, standalone `DROP INDEX index_name ON table_name`, and catalog-only `ALTER TABLE table_name RENAME INDEX\|KEY old_name TO new_name` for supported descriptor-owned secondary indexes on persistent base tables. Full key parts include integer-family, exact `DECIMAL`, canonical `YEAR`, canonical `DATE`, canonical `TIME`, canonical `DATETIME`, canonical `TIMESTAMP`, and `CHAR` / `VARCHAR` descriptors; string prefix parts are limited to `CHAR`, `VARCHAR`, and bare `TEXT` family descriptors with positive integer character lengths and current key-length diagnostics. Supported key parts may specify `ASC` or `DESC`; omitted direction is ascending. The descriptor is backed by a generated SQLite index, cloned by `CREATE TABLE ... LIKE`, omitted by `CREATE TABLE ... SELECT`, rendered in `SHOW COLUMNS`, `SHOW CREATE TABLE`, `SHOW INDEX`, and limited `INFORMATION_SCHEMA.STATISTICS`. No spatial indexes, functional key parts, visibility toggles, comments, parser options, or optimizer-use guarantees |
| Descending indexes | 🟡 | Limited `ASC` / `DESC` key-part metadata for supported persistent base-table primary, unique, nonunique, and string-prefix key parts in `CREATE TABLE`, `ALTER TABLE ... ADD PRIMARY KEY`, `ALTER TABLE ... ADD UNIQUE`, `ALTER TABLE ... ADD INDEX\|KEY`, and standalone `CREATE [UNIQUE] INDEX`. Direction is stored in MyLite descriptors, cloned by `CREATE TABLE ... LIKE`, rendered by `SHOW CREATE TABLE`, `SHOW INDEX.Collation`, and `INFORMATION_SCHEMA.STATISTICS.COLLATION`, and emitted in generated SQLite index DDL. No full optimizer-equivalence, reverse-scan reporting, fulltext/spatial/hash/multi-valued indexes, expression or table-qualified key parts, or direction semantics for foreign-key column lists |
| Prefix indexes | 🟡 | Limited string prefix key parts in `CREATE TABLE`, `ALTER TABLE ... ADD INDEX\|KEY`, and standalone `CREATE INDEX`: nonunique and unique composite prefix key parts, positive decimal character lengths on unqualified `CHAR`, `VARCHAR`, and bare `TEXT` family descriptor columns, optional `ASC` / `DESC` direction metadata, rendered through `SHOW CREATE TABLE`, `SHOW INDEX.Sub_part`, `SHOW INDEX.Collation`, and `INFORMATION_SCHEMA.STATISTICS.SUB_PART` / `COLLATION`. MyLite validates string-only prefixes, zero lengths, bounded `CHAR`/`VARCHAR` lengths, `TEXT` family byte caps such as the `TINYTEXT` 255-byte limit, duplicate key parts, and the current 3072-byte aggregate key-length envelope. No primary-key prefix enforcement, functional/table-qualified key parts, prefix optimizer guarantees, collation-complete Unicode key semantics, or index options |
| Direct JSON indexes | ⚪ | Direct indexes on `JSON` descriptor columns in supported key contexts are rejected with MySQL-compatible `3152 / 42000`; generated-column JSON path indexes and multi-valued JSON indexes remain unsupported |
| Functional key parts | ❌ | Expression key parts and metadata |
| Multi-valued indexes | ❌ | JSON array index behavior |
| FULLTEXT indexes | 🟡 | Limited metadata-only table-level `FULLTEXT [KEY\|INDEX] [name] (column[, ...])` definitions inside persistent `CREATE TABLE` for unqualified `CHAR(1..255)`, `VARCHAR(1..16383)`, `TINYTEXT`, `TEXT`, `MEDIUMTEXT`, and `LONGTEXT` descriptor columns. Omitted names use first-column suffixing, positive prefix lengths are parsed and ignored like MySQL, successful forms report zero warnings, descriptors clone through `CREATE TABLE ... LIKE`, are omitted by `CREATE TABLE ... SELECT`, and render through `SHOW COLUMNS`, `SHOW CREATE TABLE`, `SHOW INDEX`, and limited `INFORMATION_SCHEMA.STATISTICS` / `COLUMNS`; limited `ALTER TABLE ... DROP INDEX\|KEY`, standalone `DROP INDEX`, and `ALTER TABLE ... RENAME INDEX\|KEY` operate on the descriptor without physical SQLite index DDL. No `MATCH ... AGAINST`, tokenization, ranking, parser plugins, `CREATE FULLTEXT INDEX`, `ALTER TABLE ... ADD FULLTEXT`, temporary full-text indexes, `WITH PARSER`, explicit key-part direction, expression/table-qualified key parts, physical FTS tables, or optimizer/search behavior |
| SPATIAL indexes | ❌ | Geometry column requirements and spatial metadata |
| Foreign keys | 🟡 | Limited descriptor-owned integer-family foreign keys on persistent base tables, declared as table-level `FOREIGN KEY [index_name] (child_column[, ...]) REFERENCES parent(parent_column[, ...]) [ON DELETE action] [ON UPDATE action]` in `CREATE TABLE`, named single-action `ALTER TABLE ... ADD CONSTRAINT name FOREIGN KEY [index_name] ...`, or unnamed single-action `ALTER TABLE ... ADD FOREIGN KEY [index_name] ...`; action values are `CASCADE`, `RESTRICT`, and `NO ACTION`. Child and parent column lists must have matching length and exactly compatible integer-family descriptors, parent keys must be exactly matching primary or unique descriptors, child indexes are reused when their leftmost full key parts match or auto-created when missing using MySQL-compatible constraint/index-symbol naming for the admitted subset, and supported DML enforces child and parent referential checks with descriptor-built SQLite probes using `MATCH SIMPLE` NULL-tuple behavior. Direct non-recursive `ON DELETE CASCADE` and `ON UPDATE CASCADE` are applied for supported single-table `DELETE` and `UPDATE` parent writes without changing parent affected-row counts; `RESTRICT` and `NO ACTION` reject matching parent writes. Single-action `ALTER TABLE ... DROP FOREIGN KEY name` removes FK descriptors, preserves the child index and row data, and updates enforcement plus metadata. Renders ordered parts and non-default actions through `SHOW CREATE TABLE` and limited `INFORMATION_SCHEMA.TABLE_CONSTRAINTS`, `KEY_COLUMN_USAGE`, and `REFERENTIAL_CONSTRAINTS`; no non-integer keys, prefix/expression/descending FK parts, inline column references, multi-action drop/add, recursive cascades, `SET NULL`, `SET DEFAULT`, explicit `MATCH`, cross-schema references, temporary tables, mutable `foreign_key_checks`, or privilege semantics |
| Foreign key checks variable | 🟡 | Limited scalar `@@foreign_key_checks` reads report fixed enabled value `1`; no mutable checking state, disabled-enforcement mode, bulk-load optimization, or broader dependency toggling |
| Unique checks variable | 🟡 | Limited scalar `@@unique_checks` reads report fixed enabled value `1`; no mutable checking state, toggleable enforcement, optimizer effects, or import optimizations |
| CHECK constraints | 🟡 | Limited descriptor-owned table-level and inline column `CHECK` constraints in `CREATE TABLE`, plus single-action `ALTER TABLE ... ADD [CONSTRAINT [name]] CHECK`, `DROP CHECK`, and `ALTER CHECK ... [NOT] ENFORCED` for persistent base tables, including explicit names, bare `CONSTRAINT CHECK`, generated names, `ENFORCED` / `NOT ENFORCED`, integer-column boolean expressions with integer/boolean/`NULL` literals, comparisons, `<=>`, `IS NULL`, `IS NOT NULL`, unary `+` / `-` / `NOT`, arithmetic `+` / `-` / `*`, and `AND` / `OR`; enforced checks are emitted into generated SQLite table DDL and mapped back to MySQL-shaped diagnostics, enforced add/toggle validates existing rows, `INSERT IGNORE` skips violating rows with warnings, `CREATE TABLE ... LIKE` clones checks with target-generated names, CTAS omits checks, table rename updates generated logical names and rejects resulting check-name collisions, descriptor cleanup removes dropped checks, and `SHOW CREATE TABLE`, `INFORMATION_SCHEMA.CHECK_CONSTRAINTS`, and `TABLE_CONSTRAINTS` render descriptor metadata. No temporary tables, multi-action ALTER CHECK forms, `DROP CONSTRAINT` / `ALTER CONSTRAINT`, functions, variables, subqueries, string/temporal/JSON expression semantics, generated columns, collation-complete comparisons, or full MySQL expression support |
| Constraint naming | 🟡 | Limited explicit names for supported `CREATE TABLE` unique constraints that lower to existing unique-index descriptors, supported table-level foreign-key constraints, and supported checks, plus generated names for unnamed `CREATE TABLE` unique keys, foreign keys, and checks; `ALTER TABLE ... ADD CHECK` reuses the first currently available table-local generated CHECK ordinal, and duplicate supported names are rejected with current MySQL-shaped diagnostics. No named primary-key constraints, `ALTER TABLE ... ADD CONSTRAINT UNIQUE`, separate unique-constraint descriptors, or complete duplicate-name/collation compatibility |
| CREATE INDEX options | ❌ | ALGORITHM, LOCK, visibility |
| `ADD PRIMARY KEY` | 🟡 | Limited `ALTER TABLE table_name ADD PRIMARY KEY (column_name [ASC\|DESC][, ...])` for persistent base tables and existing unqualified integer-family plus ASCII-valued `CHAR(1..255)` / `VARCHAR(1..255)` descriptor columns, including composite string and mixed key tuples; validates existing rows for `NULL` with `1138 / 22004`, duplicate key tuples with `1062 / 23000`, supported ASCII string-key values, and the 3072-byte aggregate key-length envelope, reports zero affected rows and warnings, and updates ordered descriptor/physical index metadata atomically. No named constraints, primary prefix parts, non-ASCII string key values, key options, multi-action `ALTER`, generated invisible keys, or auto-increment conversion |
| `DROP PRIMARY KEY` | 🟡 | Limited single-action `ALTER TABLE table_name DROP PRIMARY KEY` for persistent base tables; deletes primary-key descriptors and the generated SQLite unique index atomically, preserves rows, columns, and supported secondary indexes, leaves former key columns `NOT NULL`, reports the table's current row count, and rejects tables without a primary key, drops that would leave an auto-increment column unindexed, or drops of keys referenced by supported foreign-key descriptors. No `DROP CONSTRAINT`, `DROP INDEX PRIMARY`, multi-action `ALTER`, temporary tables, views, algorithms, locks, cascades, triggers, or implicit-commit emulation |
| `ADD UNIQUE` | 🟡 | Limited single-action `ALTER TABLE table_name ADD UNIQUE [INDEX\|KEY] [index_name] (key_part[, ...])` for persistent base tables and existing unqualified supported descriptor columns; full unique columns cover the current scalar subset, while string prefixes cover `CHAR`, `VARCHAR`, and bare `TEXT` family descriptors including composite prefix tuples. Supported key parts may specify `ASC` or `DESC`; omitted direction is ascending. Existing duplicate non-`NULL` values, prefixes, or full-column tuples fail before mutation, duplicate `NULL` values or tuples with any `NULL` part are allowed, creates secondary-index and index-column descriptors plus one generated SQLite unique index, supports omitted-name generation with `_2`, `_3`, ... suffixes for name collisions, reports zero affected rows/warnings for non-redundant supported forms, and updates descriptor-driven `SHOW`, `CREATE TABLE ... LIKE`, limited `INFORMATION_SCHEMA`, DML duplicate checks, and index drop paths. No `ADD CONSTRAINT UNIQUE`, multi-action `ALTER`, primary-prefix/functional/table-qualified key parts, index options, comments, visibility, redundant-index warnings, temporary tables, views, or optimizer guarantees |
| `ADD INDEX` / `ADD KEY` | 🟡 | Limited single-action `ALTER TABLE table_name ADD INDEX\|KEY [index_name] (key_part[, ...])` for persistent base tables and existing unqualified supported descriptor columns, including nonunique composite indexes and nonunique `CHAR`, `VARCHAR`, and bare `TEXT` family prefix parts; supported key parts may specify `ASC` or `DESC`, with omitted direction ascending. Creates secondary-index and index-column descriptors plus one generated SQLite index, supports omitted-name generation with `_2`, `_3`, ... suffixes, reports zero affected rows/warnings, and updates descriptor-driven `SHOW`, `CREATE TABLE ... LIKE`, limited `INFORMATION_SCHEMA.STATISTICS`, DML, and auto-increment key checks. No multi-action `ALTER`, primary prefix parts, functional/table-qualified key parts, index options, comments, visibility, temporary tables, views, or optimizer guarantees |
| `ADD FULLTEXT` | ❌ | Full-text index addition |
| `ADD SPATIAL` | ❌ | Spatial index addition |
| `DROP INDEX` / `DROP KEY` | 🟡 | Limited single-action `ALTER TABLE table_name DROP INDEX\|KEY index_name` for descriptor-owned unique, nonunique secondary, and metadata-only full-text indexes on persistent base tables; deletes descriptors and the generated SQLite index when one exists, preserves rows, columns, primary keys, other secondary indexes, and allowed auto-increment descriptors, reports zero affected rows/warnings, rejects drops of indexes used by supported foreign-key descriptors, and updates descriptor-driven `SHOW`, `CREATE TABLE ... LIKE`, limited `INFORMATION_SCHEMA`, and DML behavior. No primary-key drops through `DROP INDEX`, multi-action `ALTER`, temporary tables, views, algorithms, locks, cascades, triggers, or optimizer guarantees |
| `RENAME INDEX` / `RENAME KEY` | 🟡 | Limited single-action persistent base-table `ALTER TABLE table_name RENAME INDEX\|KEY old_name TO new_name` for descriptor-owned unique, nonunique secondary, and metadata-only full-text indexes; renames the logical catalog descriptor only, preserves the generated SQLite physical index when one exists, key parts, uniqueness, rows, foreign-key references by index id, and index metadata, supports exact same-name and case-only spelling changes, reports zero affected rows/warnings, and updates descriptor-driven `SHOW`, `CREATE TABLE ... LIKE`, limited `INFORMATION_SCHEMA`, and DML diagnostics. No primary-key renames, multi-action `ALTER`, algorithms, locks, temporary tables, views, index visibility, or optimizer guarantees |
| `ALTER INDEX VISIBLE` / `INVISIBLE` | ❌ | Index visibility metadata and optimizer behavior |
| `ADD CONSTRAINT CHECK` | 🟡 | Limited single-action `ALTER TABLE table_name ADD [CONSTRAINT [name]] CHECK (expression) [[NOT] ENFORCED]` for persistent base tables using the current CHECK expression subset; enforced adds validate existing rows and report the scan count, while not-enforced adds update descriptors only and report zero rows. No multi-action forms, broader expressions, temporary tables, algorithms, locks, or privilege semantics |
| `DROP CHECK` | 🟡 | Limited single-action `ALTER TABLE table_name DROP CHECK check_name` for descriptor-owned CHECK constraints on persistent base tables; removes metadata, rebuilds only when an enforced physical CHECK must be removed, reports zero rows, and updates descriptor-driven metadata. No `DROP CONSTRAINT`, multi-action forms, temporary tables, algorithms, locks, cascades, or privilege semantics |
| `ALTER CHECK ENFORCED` / `NOT ENFORCED` | 🟡 | Limited single-action `ALTER TABLE table_name ALTER CHECK check_name ENFORCED\|NOT ENFORCED` for descriptor-owned CHECK constraints on persistent base tables; enforcing validates existing rows and reports the scan count, unenforcing removes physical enforcement and reports zero rows, and idempotent toggles are metadata no-ops. No `ALTER CONSTRAINT`, multi-action forms, temporary tables, algorithms, locks, or privilege semantics |
| `ADD CONSTRAINT FOREIGN KEY` | 🟡 | Limited named single-action `ALTER TABLE child ADD CONSTRAINT name FOREIGN KEY [index_name] (child_column[, ...]) REFERENCES parent(parent_column[, ...]) [ON DELETE action] [ON UPDATE action]` plus unnamed `ALTER TABLE child ADD FOREIGN KEY [index_name] ...` for persistent base tables and one-or-more exactly compatible integer-family child/parent column pairs in the same schema; action values are `CASCADE`, `RESTRICT`, and `NO ACTION`. Validates existing child rows, reuses or auto-creates a matching child index with MySQL-compatible constraint/index-symbol naming for the admitted subset, records ordered descriptor metadata atomically, and reports zero affected rows/warnings. No non-integer keys, prefix/expression/descending parts, cross-schema references, recursive cascades, `SET NULL`, `SET DEFAULT`, explicit `MATCH`, temporary tables, views, algorithms, locks, or multi-action ALTER |
| `DROP FOREIGN KEY` | 🟡 | Limited single-action `ALTER TABLE table_name DROP FOREIGN KEY foreign_key_name` for descriptor-owned integer-family foreign keys on persistent base tables. Success removes foreign-key and foreign-key-column descriptors atomically, increments the table descriptor generation, preserves child indexes and rows, performs no physical SQLite DDL, reports zero affected rows/warnings, and updates descriptor-driven `SHOW CREATE TABLE`, `SHOW INDEX`, limited `INFORMATION_SCHEMA`, and DML enforcement. Missing FKs fail with `1091 / 42000`; no `IF EXISTS`, `DROP CONSTRAINT`, multi-action `ALTER`, algorithms, locks, temporary tables, views, triggers, recursive cascade cleanup, or privilege semantics |
| `DISABLE KEYS` / `ENABLE KEYS` | ❌ | MyISAM-style key maintenance syntax, diagnostics |
