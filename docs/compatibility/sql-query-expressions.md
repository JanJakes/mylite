# SQL query expressions

Core query expression, SELECT, set operation, ordering, limiting, locking, modifier, and result metadata compatibility.

| Feature | Status | Notes |
| --- | --- | --- |
| `SELECT` | 🟡 | Descriptor-driven single persistent base-table `SELECT *`, `SELECT column [AS alias][, column [AS alias] ...] FROM table`, explicit `SELECT ALL` on supported non-distinct forms, limited no-source and `FROM DUAL` mixed session-scalar plus scalar-value projection over current session scalar functions/system variables, decimal integer/`NULL`/boolean literal select items, scalar `IF()`/`IFNULL()`/`COALESCE()`/`NULLIF()`/`ISNULL()` values with signed-64 integer/boolean/`NULL` operands and supported nested scalar function calls, limited no-source/`DUAL` signed-64 scalar arithmetic projection for `+`, binary `-`, `*`, unary `+`, unary `-`, `%`, infix `MOD`, `MOD(left, right)`, and infix `DIV`, and specified upcoming limited no-source/`DUAL` signed-64 scalar comparison projection for `=`, `<=>`, `<>`, `!=`, `<`, `<=`, `>`, and `>=`, plus limited one-column `SELECT DISTINCT` / `DISTINCTROW column [AS alias] FROM table` with optional limited source table alias, descriptor-qualified column references, `WHERE`, single-column `ORDER BY`, and `LIMIT`/`OFFSET`, plus limited one-item `COUNT(*)` and `COUNT(integer/NULL/boolean literal)` with no source, `FROM DUAL`, or one descriptor-backed table with optional baseline table alias and `WHERE`, limited one-item `COUNT(column)` and `COUNT(DISTINCT column)` over one descriptor-backed table with optional baseline table alias, qualified column argument, and `WHERE`, limited one-item `MIN(column)` / `MAX(column)` / `SUM(column)` / `AVG(column)`, and limited one-item `BIT_AND(column)` / `BIT_OR(column)` / `BIT_XOR(column)` over one descriptor-backed table with optional baseline table alias, qualified column argument, and `WHERE`; also supports limited grouped aggregates as `SELECT group_column, aggregate FROM table [WHERE ...] GROUP BY group_column [HAVING grouped_or_selected_aggregate_predicate] [ORDER BY group_column] [LIMIT ...]` for one descriptor group column and one supported aggregate result; supported non-wildcard select items may use identifier, quoted-identifier, or string-literal aliases as result labels; `SELECT *` expands visible descriptor columns only, while explicit column, predicate, order, distinct, group, having, and aggregate references may name invisible columns; top-level scalar integer literals keep the existing literal-projection envelope while scalar arithmetic operands and scalar function operands remain signed-64; `SUM(column)` and `AVG(column)` are limited to MyLite's current signed-64 aggregate envelope, and bitwise aggregates return unsigned-64 decimal text for integer descriptor columns; no general expression projection, table-backed literal/expression projection, qualified wildcards, joins, full grouping, locking, mutable `sql_select_limit` row caps, `sql_buffer_result` temporary result buffering, `sql_auto_is_null` auto-increment lookup behavior, `sql_big_selects` row-estimate aborts, or arbitrary SQLite pass-through |
| Query expression grammar | ❌ | Query terms and primaries |
| Projection list | 🟡 | Wildcard uses visible descriptor columns in catalog ordinal order; explicit table projections and limited one-column `SELECT DISTINCT` / `DISTINCTROW` resolve descriptor column names, including invisible columns and supported source-qualified references; no-source and `FROM DUAL` projection may return mixed session-scalar plus scalar-value item lists over current session scalar functions/system variables, decimal integer, `NULL`, `TRUE`, and `FALSE` literal select items, scalar `IF()`/`IFNULL()`/`COALESCE()`/`NULLIF()`/`ISNULL()` values with signed-64 integer/boolean/`NULL` operands and supported nested scalar calls, limited signed-64 `+`, binary `-`, `*`, unary `+`, unary `-`, `%`, infix `MOD`, `MOD(left, right)`, and infix `DIV` arithmetic over the current scalar-value domain, and specified upcoming signed-64 scalar comparison projection for `=`, `<=>`, `<>`, `!=`, `<`, `<=`, `>`, and `>=`; top-level scalar integer literals keep the existing literal-projection envelope while scalar arithmetic operands and scalar function operands remain signed-64; supported non-wildcard items may use identifier, quoted-identifier, or string-literal aliases as result labels; limited one-item `COUNT(*)`, `COUNT(column)`, `COUNT(integer/NULL/boolean literal)`, `COUNT(DISTINCT column)`, `MIN(column)`, `MAX(column)`, signed-64-range `SUM(column)`, signed-64-intermediate `AVG(column)`, and unsigned-64-text `BIT_AND(column)` / `BIT_OR(column)` / `BIT_XOR(column)` aggregate forms are supported; grouped aggregate projection is limited to one descriptor group column and one aggregate result; duplicate projected descriptor columns and duplicate labels are allowed for non-distinct selects; no expression metadata, table-backed expression projection, qualified wildcards, or full multi-expression distinct rows |
| Table aliases | 🟡 | Optional `AS alias` or bare `alias` on supported single persistent base-table `SELECT` sources; selected columns, predicates, order keys, and aggregate arguments may be qualified by that alias, while unaliased sources may use table or schema-table qualifiers; no qualified wildcards, joins, duplicate alias checks for multi-table sources, index hints, or derived tables |
| `SELECT ... FROM DUAL` | 🟡 | Limited scalar/session-function projection, mixed session-scalar plus scalar-value projection over current session scalar functions/system variables, decimal integer/`NULL`/boolean literal select items, scalar `IF()`/`IFNULL()`/`COALESCE()`/`NULLIF()`/`ISNULL()` values with signed-64 integer/boolean/`NULL` operands and supported nested scalar calls, limited signed-64 `+`, binary `-`, `*`, unary `+`, unary `-`, `%`, infix `MOD`, `MOD(left, right)`, and infix `DIV` scalar arithmetic projection, specified upcoming signed-64 scalar comparison projection for `=`, `<=>`, `<>`, `!=`, `<`, `<=`, `>`, and `>=`, and one-item `COUNT(*)` / `COUNT(integer/NULL/boolean literal)` one-row semantics; no table-backed descriptor behavior or arbitrary expression evaluation |
| `WHERE` | 🟡 | Descriptor-backed boolean expressions over existing predicate atoms for filtered table `SELECT`, aggregate source filters, `DELETE`, and `UPDATE`: keyword `NOT`, `AND`/`&&`, `XOR`, `OR`/`\|\|`, and parentheses follow MySQL precedence, `SELECT` may use supported source-qualified references, while `DELETE` and `UPDATE` remain unqualified; integer comparisons with a non-`NULL` decimal integer or `TRUE`/`FALSE` right operand (`=`, `<=>`, `<>`, `!=`, `<`, `<=`, `>`, `>=`), limited `BETWEEN` / `NOT BETWEEN` with two decimal integer or `TRUE`/`FALSE` bounds, limited `IN` / `NOT IN` with a nonempty decimal integer/`TRUE`/`FALSE`/`NULL` list, normal stored-value `IS NULL` and `IS NOT NULL`, plus descriptor-column `IS [NOT] TRUE` / `FALSE` / `UNKNOWN` truth tests; `XOR` propagates `NULL` for the admitted predicate subset, `&&` and `\|\|` record MySQL-compatible deprecation warning 1287; no `WHERE TRUE`, symbolic `!`, scalar expression `XOR`, literal-left comparisons, expression-left truth tests, `col = NULL`, `sql_auto_is_null` auto-increment lookup behavior, functions, parameters, string/decimal/float/hex/bit literals, subqueries, row constructors, or general expression predicates |
| `GROUP BY` | 🟡 | Limited single descriptor group column with one supported aggregate result over one descriptor-backed persistent base table: `SELECT group_column, aggregate FROM table [WHERE ...] GROUP BY group_column [HAVING grouped_or_selected_aggregate_predicate] [ORDER BY group_column [ASC|DESC]] [LIMIT ...]`; `NULL` keys form one group, optional `HAVING` filters groups after aggregation, optional ordering follows existing integer/`NULL` order semantics, and limiting follows existing SELECT `LIMIT`/`OFFSET`; no multiple grouping keys, grouping aliases, ordinals, expressions, rollup, functional-dependence analysis, aggregate-only grouped projection, grouped `COUNT(DISTINCT)`, joins, or full `ONLY_FULL_GROUP_BY` coverage |
| `WITH ROLLUP` | ❌ | Super-aggregate rows and GROUPING() behavior |
| `HAVING` | 🟡 | Limited post-group predicates on the existing grouped aggregate subset only: one grouped descriptor integer column or its alias, or the selected `COUNT(*)`, `COUNT(column)`, `MIN(column)`, `MAX(column)`, `SUM(column)`, or `AVG(column)` aggregate expression or alias, compared to an integer/boolean literal or tested with `IS NULL` / `IS NOT NULL`; no non-grouped `HAVING`, boolean composition, bare truth tests, aggregate expressions not selected, `COUNT(DISTINCT)`, bitwise aggregate result predicates, arbitrary expressions, subqueries, or general alias ambiguity handling |
| Window definitions | ❌ | Named windows, frames, restrictions |
| `ORDER BY` | 🟡 | One descriptor column for supported base-table `SELECT`, `DELETE`, and `UPDATE`; `SELECT` may use supported source-qualified references or one unqualified select-item alias, while `DELETE` and `UPDATE` remain unqualified descriptor-only forms; aliases shadow descriptor column names and duplicate matching aliases are ambiguous; optional `ASC`/`DESC`; `ASC` is the default, `NULL` sorts before non-`NULL` ascending and after non-`NULL` descending; limited `SELECT DISTINCT column [AS alias]` requires the order key to resolve to the selected column or its alias; limited grouped aggregates may order only by the grouped descriptor column or its alias; no ordinals, expressions, string-literal order keys, qualified wildcards, collations, multiple keys, aggregate alias ordering, or tie-order guarantee |
| `LIMIT` / `OFFSET` | 🟡 | Supported base-table `SELECT` forms are `LIMIT row_count`, `LIMIT row_count OFFSET offset`, and `LIMIT offset, row_count`; supported single-table `DELETE` and `UPDATE` admit only `LIMIT row_count`; all supported forms use unsigned decimal integer literals in the signed 64-bit range; `LIMIT 0` returns no rows for `SELECT` and matches no rows for supported DML; no signed, string, decimal, float, hex, bit, parameter, or expression limits |
| `@@sql_auto_is_null` | 🟡 | Limited scalar reads expose the fixed disabled value `0`; no mutable session state, `AUTO_INCREMENT` metadata, `LAST_INSERT_ID()`-driven special lookup behavior, or special `IS NULL` lookup behavior |
| `@@sql_big_selects` | 🟡 | Limited scalar reads expose the fixed enabled value `1`; no mutable session state, `max_join_size`, optimizer row-estimate aborts, or changed descriptor-backed `SELECT` execution |
| `@@sql_buffer_result` | 🟡 | Limited scalar reads expose the fixed disabled value `0`; no mutable session state, temporary result table materialization, lock-release behavior, or changed descriptor-backed `SELECT` execution |
| `@@sql_select_limit` | 🟡 | Limited scalar reads expose the fixed no-limit value `18446744073709551615`; no mutable session state and no implicit row caps for descriptor-backed `SELECT` |
| `ALL` select modifier | 🟡 | Explicit `SELECT ALL` is accepted as the duplicate-preserving default for currently supported session scalar, scalar value projection, `DUAL`, descriptor-backed table column-list, table-backed wildcard, and aggregate select forms; no repeated `ALL`, mixed `ALL DISTINCT` / `ALL DISTINCTROW`, or other select modifiers |
| `DISTINCT` / `DISTINCTROW` | 🟡 | Limited one-column `SELECT DISTINCT column [AS alias] FROM table` and synonymous `SELECT DISTINCTROW column [AS alias] FROM table` over one descriptor-backed persistent base table with optional source table alias, source-qualified column references, baseline `WHERE`, optional `ORDER BY` resolving to the same selected column or its alias, and existing select `LIMIT`/`OFFSET`; integer/`NULL` descriptor columns only, no wildcard, multiple select items, expressions, literals, full multi-column duplicate rows, grouping, joins, or protocol-grade metadata |
| `UNION` | ❌ | ALL/DISTINCT, metadata, ordering |
| `INTERSECT` | ❌ | set operator semantics |
| `EXCEPT` | ❌ | set operator semantics |
| `TABLE` | ❌ | Table-value statement syntax and ordering/limit behavior |
| `VALUES` | ❌ | Standalone values statement and row constructor behavior |
