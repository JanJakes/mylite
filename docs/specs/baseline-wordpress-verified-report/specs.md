# Baseline WordPress Verified Report

## Status

This slice tracks the PHP extension branch's WordPress SQLite-driver verified
report. The report is generated by
`experiments/wp-sqlite-tests/run-verified.sh`, which runs the upstream
`packages/mysql-on-sqlite/tests` suite through the MyLite mysqli experiment
harness and replays MySQL 8.4.9 assertion overrides.

The current refreshed report after the harness shims and focused core fixes is:

- total: 442
- passed: 347
- failed: 50
- skipped: 45
- failure classes: 34 `mylite-query-error`, 16 `assertion-divergence`

## Scope

The batch covers every remaining failure in
`build/wp-sqlite-mylite-verified-results.json`. Fixes may land in either of two
places:

- MyLite core, when the failing SQL exposes a MySQL 8.4.9 compatibility gap in
  parser, runtime, metadata, diagnostics, DDL, DML, functions, result metadata,
  or mysqli extension behavior.
- The WordPress experiment harness, when the upstream test directly depends on
  SQLite-driver internals, a reduced PHPUnit shim method, or synthetic
  SQLite-only introspection that is not MyLite SQL.

Harness accommodations must remain narrow and must not redefine MyLite core SQL
semantics. Core compatibility fixes must keep MySQL 8.4.9 behavior as the
authority and use real MySQL expectations where a behavior is not already
covered by an existing baseline script.

The harness also consumes the MySQL 8.4.9 baseline result file and records
tests that fail against MySQL itself as skipped MyLite cases. These rows remain
visible in the report with their baseline failure class and message, but they
are not treated as MyLite regressions.

## Failure Clusters

- Experiment harness / SQLite-driver internals:
  missing PHPUnit helpers, direct `PRAGMA index_list` /
  `pragma_index_xinfo` calls, direct `sqlite_master` reads, and private helper
  calls in upstream tests.
- Metadata and collation:
  `INFORMATION_SCHEMA.TABLES`, `SHOW TABLE STATUS`, `SHOW COLLATION WHERE`,
  `INFORMATION_SCHEMA.COLLATIONS`, table status timestamps, table collation,
  database listing order, and result-column metadata.
- Auto-increment and identity:
  `INFORMATION_SCHEMA.TABLES.AUTO_INCREMENT`, `SHOW TABLE STATUS`, explicit
  `AUTO_INCREMENT=N` table options, temporary-table auto-increment, and
  mysqli `insert_id`.
- DDL, indexes, and constraints:
  primary-key changes through `ALTER TABLE`, inline foreign keys, composite
  foreign keys, drop primary key/index behavior, check-constraint descriptors,
  complex index option tails, duplicate constraint/key names, and `IF NOT
  EXISTS` no-op behavior.
- Query expressions and functions:
  `CONCAT`, string length/slice functions in row queries, `LIKE` expressions,
  `HAVING` without `GROUP BY`, `BINARY` predicates, `CURRENT_TIMESTAMP`,
  casts/converts, base64 functions, `RAND`, date functions, and scalar numeric
  coercion cases reached by the WordPress tests.
- DML and table references:
  update/delete limit and join forms, target-table self-subquery cases, insert
  select from `DUAL`, complex information-schema queries, savepoints, and
  temporary-table precedence.
- PHP mysqli metadata:
  native type IDs, display lengths, table names for zero-row results, and
  expression-column metadata surfaced through `mysqli_result::fetch_fields()`.

## Non-Goals

This batch must not:

- copy or depend on upstream WordPress, MySQL, MariaDB, Percona, or SQLite
  implementation internals;
- add a broad SQLite-driver emulation mode to core MyLite SQL;
- move MyLite compatibility logic into the SQLite fork;
- mark a core MySQL-compatible behavior unsupported just because the upstream
  SQLite-driver test has a different internal assertion;
- skip or delete failing tests to improve the report.

## Verification

Each cluster must be verified with the narrowest useful tests first, then with:

- applicable MySQL 8.4.9 expectation scripts or newly added expectation probes;
- focused CTest targets for changed MyLite core behavior;
- PHP harness syntax/build checks when the experiment harness changes;
- `experiments/wp-sqlite-tests/run-verified.sh` after each meaningful cluster;
- `git diff --check`, `git diff --cached --check`, and the relevant CMake
  release gate before committing completed slices.
