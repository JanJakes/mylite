# SQL table DML

Table-shaped data modification, import, replace, and direct table access
statements.

| Feature | Status | Notes |
| --- | --- | --- |
| `DELETE` (single-table) | 🟡 | Limited persistent base-table `DELETE FROM table` with optional baseline integer/`NULL` `WHERE` predicate boolean expression, including keyword `NOT`, `AND`/`&&`, `XOR`, `OR`/`\|\|`, limited `BETWEEN` range predicates, limited `IN` membership predicates, and descriptor-column `IS [NOT] TRUE` / `FALSE` / `UNKNOWN`, one unqualified descriptor `ORDER BY` column, optional `ASC`/`DESC`, exact affected rows, and `LIMIT row_count` using unsigned decimal literals in signed 64-bit range; no aliases, partitions, modifiers, joined deletes, `USING`, full ordering, offset forms, triggers, cascades, foreign keys, or privilege semantics |
| `DELETE` (multi-table) | ❌ | Multi-table forms and affected rows |
| `HANDLER` | ❌ | HANDLER OPEN, READ, and CLOSE cursor-like table access |
| `INSERT ... VALUES` | 🟡 | Limited single- and multi-row `INSERT [LOW_PRIORITY \| HIGH_PRIORITY \| DELAYED] [IGNORE] [INTO] table_name ... VALUES ...` into persistent base tables with optional unqualified column lists, integer/`NULL`/`TRUE`/`FALSE`/`DEFAULT` values plus ordinary string literals for `VARCHAR` targets, descriptor-driven assignment, omitted columns and explicit `DEFAULT` values filled from descriptor integer defaults or effective `NULL` defaults, limited generated values for the current auto-increment primary-key subset, strict range/nullability/no-default/string-length diagnostics, single-column integer primary-key duplicate enforcement, affected rows, all-or-nothing statement behavior, no-op `LOW_PRIORITY` / `HIGH_PRIORITY`, warning-producing deprecated `DELAYED`, and limited `IGNORE` warning demotion for omitted no-explicit-default columns, explicit `DEFAULT` for no-default columns, explicit `NULL` into numeric or `VARCHAR` `NOT NULL`, integer range clipping, and duplicate primary-key rows; no-column-list inserts target visible descriptor columns only, while explicit column lists may name invisible columns; nullable dropped-default columns warn and store `NULL`, numeric `NOT NULL` no-default columns warn and store `0`, and `VARCHAR NOT NULL` no-default columns warn and store empty strings; no mixed-mode multi-row auto-increment gap emulation, `DEFAULT(col_name)`, string truncation warning demotion, `ON DUPLICATE KEY UPDATE`, or `SELECT` form |
| `INSERT ... SET` | 🟡 | Limited one-row `INSERT [LOW_PRIORITY \| HIGH_PRIORITY \| DELAYED] [IGNORE] [INTO] table_name SET column_name = value[, ...]` into persistent base tables with unqualified assignment columns, supported decimal integer/`NULL`/`TRUE`/`FALSE`/`DEFAULT` values plus ordinary string literals for `VARCHAR` targets, descriptor-driven assignment including invisible columns when explicitly named, omitted columns and explicit `DEFAULT` values filled from descriptor integer defaults or effective `NULL` defaults, limited generated values for the current auto-increment primary-key subset, strict required-column/range/nullability/string-length diagnostics, single-column integer primary-key duplicate enforcement, one affected row, all-or-nothing statement behavior, no-op `LOW_PRIORITY` / `HIGH_PRIORITY`, warning-producing deprecated `DELAYED`, and limited `IGNORE` warning demotion for omitted no-explicit-default columns, explicit `DEFAULT` for no-default columns, explicit `NULL` into numeric or `VARCHAR` `NOT NULL`, integer range clipping, and duplicate primary-key rows; nullable dropped-default columns warn and store `NULL`, numeric `NOT NULL` no-default columns warn and store `0`, and `VARCHAR NOT NULL` no-default columns warn and store empty strings; no table-qualified assignment targets, expression assignments, `DEFAULT(col_name)`, string truncation warning demotion, aliases, partitions, `ON DUPLICATE KEY UPDATE`, or `SELECT` form |
| `INSERT ... SELECT` | 🟡 | Limited descriptor-backed `INSERT [LOW_PRIORITY \| HIGH_PRIORITY \| DELAYED] [INTO] target [(column_name[, ...])] SELECT ... FROM source` for persistent base tables without primary-key descriptors, reusing the existing single-table source `SELECT` subset with optional table alias, `WHERE`, one-column integer `ORDER BY`, `LIMIT`, and simple no-op source locking clauses; target column lists are descriptor-driven, omitted targets receive descriptor integer defaults or effective nullable `NULL` only for rows actually inserted, source/target `*` and omitted target lists use visible columns, explicit columns may name invisible columns, selected integer/`NULL` and compatible `VARCHAR` `TEXT` values are validated against target descriptors, `LOW_PRIORITY` / `HIGH_PRIORITY` are no-ops, and `DELAYED` records MySQL's deprecated-delayed warning; no key-bearing targets, `IGNORE`, partitions, `ON DUPLICATE KEY UPDATE`, `TABLE`, row constructors, joins, CTEs, literal/expression projection sources, auto-increment, triggers, generated columns, locking options, warning demotion, string/integer conversion, or general expression conversion |
| `INSERT ... ON DUPLICATE KEY UPDATE` | ❌ | Conflict handling and warnings |
| `INSERT IGNORE` | 🟡 | Limited `INSERT IGNORE ... VALUES` and `INSERT IGNORE ... SET` warning demotion for descriptor integer/`NULL`/`DEFAULT` inputs, admitted `VARCHAR` null/default adjustments, generated values for the current auto-increment primary-key subset, and duplicate rows for the current single-column integer primary-key subset; nonconflicting rows continue and affected rows count rows actually inserted. Omitted no-explicit-default columns and explicit `DEFAULT` for no-default columns warn and store `0` for numeric `NOT NULL`, empty string for `VARCHAR NOT NULL`, or `NULL` for nullable dropped-default columns, explicit `NULL` into numeric `NOT NULL` stores `0` and explicit `NULL` into `VARCHAR NOT NULL` stores empty string with warnings, out-of-range integer values clip to the supported descriptor range with warnings, and non-ignorable syntax/name/shape errors remain errors; no `INSERT IGNORE ... SELECT`, partitions, `DEFAULT(col_name)`, overlength string warning demotion, decimal/float/hex/bit conversion, general expression conversion, or full non-strict mode behavior |
| `INSERT DELAYED` | 🟡 | Limited modifier support on currently supported `INSERT ... VALUES`, `INSERT ... SET`, and descriptor-backed `INSERT ... SELECT` forms; executes as ordinary `INSERT` and records warning `3005`; `VALUES` and `SET` may combine `DELAYED IGNORE` with delayed warning before adjustment warnings; no delayed queues, background writes, storage scheduling, or `INSERT IGNORE ... SELECT` |
| `INSERT LOW_PRIORITY` / `HIGH_PRIORITY` | 🟡 | Limited no-op priority modifier support on currently supported `INSERT ... VALUES`, `INSERT ... SET`, and descriptor-backed `INSERT ... SELECT` forms; `VALUES` and `SET` may combine one priority modifier before `IGNORE`; no table-lock scheduling semantics, multiple modifiers, or `INSERT IGNORE ... SELECT` |
| `LOAD DATA INFILE` | ❌ | Server-side import syntax |
| `LOAD DATA LOCAL INFILE` | ❌ | LOCAL INFILE flow and security |
| `LOAD XML INFILE` | ❌ | XML import syntax |
| `LOAD XML LOCAL INFILE` | ❌ | Client-side XML import request behavior diagnostics |
| `REPLACE ... VALUES` | 🟡 | Limited no-key-descriptor `REPLACE [LOW_PRIORITY \| DELAYED] [INTO] table_name [(column_name[, ...])] VALUES (value[, ...])[, ...]` insert-equivalent path for persistent base tables without primary-key descriptors, with integer/`NULL`/`TRUE`/`FALSE`/`DEFAULT` values plus ordinary string literals for `VARCHAR` targets, descriptor column resolution including explicitly named invisible columns, omitted-column and explicit-`DEFAULT` descriptor default filling, strict range/nullability/no-default/string-length diagnostics, affected rows equal to inserted rows, all-or-nothing statement behavior, no-op `LOW_PRIORITY`, and warning-producing deprecated `DELAYED`; key-bearing targets are rejected until delete-insert semantics are specified, and there is no `VALUE` synonym, row constructors, partitions, `DEFAULT(col_name)`, generated values, warning demotion, string truncation warning demotion, or insert ids |
| `REPLACE ... SET` | 🟡 | Limited no-key-descriptor one-row `REPLACE [LOW_PRIORITY \| DELAYED] [INTO] table_name SET column_name = value[, ...]` insert-equivalent path for persistent base tables without primary-key descriptors, with unqualified descriptor assignment targets, integer/`NULL`/`TRUE`/`FALSE`/`DEFAULT` values plus ordinary string literals for `VARCHAR` targets, omitted-column and explicit-`DEFAULT` descriptor default filling, strict range/nullability/no-default/string-length diagnostics, one affected row, all-or-nothing statement behavior, no-op `LOW_PRIORITY`, and warning-producing deprecated `DELAYED`; key-bearing targets are rejected until delete-insert semantics are specified, and there are no partitions, qualified assignment targets, expression assignments, `DEFAULT(col_name)`, `VALUES`, `SELECT` forms, or string truncation warning demotion |
| `REPLACE ... SELECT` | 🟡 | Limited no-key-descriptor `REPLACE [LOW_PRIORITY \| DELAYED] [INTO] target [(column_name[, ...])] SELECT ... FROM source` insert-equivalent path for persistent base tables without primary-key descriptors, reusing the existing single-table source `SELECT` subset with optional table alias, `WHERE`, one-column integer `ORDER BY`, `LIMIT`, and simple no-op source locking clauses; target column lists are descriptor-driven, omitted targets receive descriptor integer defaults or effective nullable `NULL` only for rows actually inserted, source/target `*` and omitted target lists use visible columns, explicit columns may name invisible columns, and selected integer/`NULL` plus compatible `VARCHAR` `TEXT` values are validated against target descriptors; key-bearing targets are rejected until delete-insert semantics are specified, and there are no partitions, `TABLE`, joins, CTEs, literal/expression projection sources, generated values, locking options, warning demotion, string/integer conversion, or insert ids |
| `REPLACE LOW_PRIORITY` / `DELAYED` | 🟡 | Limited modifier support on currently supported no-key `REPLACE` forms: `LOW_PRIORITY` is accepted as a no-op and `DELAYED` executes as ordinary `REPLACE` with warning `3005`; no multiple modifiers, `HIGH_PRIORITY`, delayed queues, storage scheduling changes, or duplicate-key replacement semantics |
| `UPDATE` (single-table) | 🟡 | Limited persistent base-table `UPDATE table_name SET column_name = value` with one unqualified assignment column, supported decimal integer/`NULL`/`TRUE`/`FALSE`/`DEFAULT` assignment values plus ordinary string literals for `VARCHAR` targets, optional baseline `WHERE` predicate boolean expression including keyword `NOT`, `AND`/`&&`, `XOR`, `OR`/`\|\|`, limited integer `BETWEEN` range predicates, limited integer `IN` membership predicates, descriptor-column `IS [NOT] TRUE` / `FALSE` / `UNKNOWN` for integer columns, and `IS NULL` / `IS NOT NULL` for integer or `VARCHAR` columns, optional one-column integer `ORDER BY` with `ASC`/`DESC`, optional `LIMIT row_count` using unsigned decimal literals in signed 64-bit range, duplicate-key errors when updating the current single-column integer primary-key column to an existing value, and changed-row affected counts; assignment, predicate, and ordering columns resolve through descriptors and may explicitly name invisible columns; no aliases, table-qualified assignment targets, multiple assignments, expression assignments, string/integer conversion, `DEFAULT(col_name)`, partitions, modifiers, joined updates, multi-table updates, string ordering/comparison predicates, table-qualified/order expression/ordinal/multiple-key ordering, offset forms, triggers, cascades, foreign keys, generated columns, or privilege semantics |
| `UPDATE` (multi-table) | ❌ | Joined update semantics |
| SQL safe updates variable | 🟡 | Limited scalar `@@sql_safe_updates` reads report fixed disabled value `0`; no mutable safe-updates state, `sql_select_limit`, `max_join_size`, key-aware DML checks, or changed `UPDATE`/`DELETE` behavior |
| SQL warnings variable | 🟡 | Limited scalar `@@sql_warnings` reads report fixed disabled value `0`; limited `INSERT IGNORE ... VALUES` / `SET` adjustment warnings are still recorded in diagnostics like MySQL; no mutable warning-reporting state, broader warning-producing insert conversions, strict warning demotion beyond the limited `INSERT IGNORE` subset, or single-row insert information strings |
