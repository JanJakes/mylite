# SQL indexes and constraints

Standalone index statements plus index, key, constraint, foreign-key, and check DDL details.

## Statement surface

| Feature | Status | Notes |
| --- | --- | --- |
| `CREATE INDEX` | 🟡 | Limited standalone `CREATE INDEX index_name ON table_name (column_name)` and `CREATE UNIQUE INDEX index_name ON table_name (column_name)` for persistent base tables, one explicit index name, and one existing unqualified supported descriptor column; creates descriptor-owned index metadata plus one generated SQLite index, reports zero affected rows/warnings, validates existing duplicate rows for unique indexes, and updates descriptor-driven `SHOW`, `CREATE TABLE ... LIKE`, limited `INFORMATION_SCHEMA`, DML duplicate checks, and `ALTER TABLE ... DROP INDEX\|KEY`. No omitted names, `IF NOT EXISTS`, standalone `DROP INDEX`, fulltext/spatial indexes, primary-key creation, composite/prefix/descending/functional key parts, options, comments, visibility, algorithms, locks, temporary tables, views, or optimizer guarantees |
| `DROP INDEX` | ❌ | Standalone index removal semantics |
| `CACHE INDEX` | ❌ | MyISAM key cache assignment syntax |
| `LOAD INDEX INTO CACHE` | ❌ | MyISAM index preload syntax |

## Index and constraint details

| Feature | Status | Notes |
| --- | --- | --- |
| Primary keys | 🟡 | Limited descriptor-owned integer-family primary keys declared in `CREATE TABLE`, plus single-column ASCII-valued `CHAR(1..255)` / `VARCHAR(1..255)` primary keys declared in `CREATE TABLE` or added later with `ALTER TABLE ... ADD PRIMARY KEY (column)`, and keys removed with `ALTER TABLE ... DROP PRIMARY KEY`. Create-time integer keys support inline/table-level single-column and table-level composite forms; string keys are deliberately single-column only. Added keys validate existing rows for `NULL`, duplicate key tuples, and supported ASCII string-key values, make every key-part descriptor column `NOT NULL`, preserve supported defaults and secondary indexes, and create a generated SQLite unique index with the MyLite `utf8mb4_0900_ai_ci` ASCII collation annotation for string key parts. Dropped keys remove the descriptor rows and generated physical index, preserve rows, column descriptors, and supported secondary indexes, leave former key columns `NOT NULL`, report the current table row count, and keep an auto-increment column only if a supported secondary index still indexes it. Existing DML enforces duplicate keys for current `INSERT ... VALUES` / `INSERT ... SET`, `INSERT IGNORE`, and single-assignment `UPDATE`; `CREATE TABLE ... LIKE`, `SHOW COLUMNS` / `SHOW INDEX` / `SHOW CREATE TABLE`, and limited `INFORMATION_SCHEMA.COLUMNS.COLUMN_KEY`, `INFORMATION_SCHEMA.STATISTICS`, `INFORMATION_SCHEMA.TABLE_CONSTRAINTS`, and `INFORMATION_SCHEMA.KEY_COLUMN_USAGE` metadata observe the descriptor. No composite string primary keys, non-ASCII string key values, named constraints, foreign keys, auto-increment conversion, or optimizer/index-use guarantees |
| Unique indexes | 🟡 | Limited descriptor-owned single-column unique indexes declared inside `CREATE TABLE` with inline `UNIQUE` / `UNIQUE KEY`, table-level `UNIQUE [KEY\|INDEX] [name] (column)`, or standalone `CREATE UNIQUE INDEX index_name ON table_name (column_name)` on integer-family, exact `DECIMAL`, canonical `DATE`, canonical `DATETIME`, canonical `TIMESTAMP`, and ASCII-valued `CHAR(1..255)` / `VARCHAR(1..255)` descriptors. The descriptor is backed by a generated SQLite unique index, using the MyLite `utf8mb4_0900_ai_ci` ASCII collation annotation for string key parts, cloned by `CREATE TABLE ... LIKE`, omitted by `CREATE TABLE ... SELECT`, removable with limited `ALTER TABLE ... DROP INDEX\|KEY`, rendered in `SHOW COLUMNS`, `SHOW CREATE TABLE`, `SHOW INDEX`, and limited `INFORMATION_SCHEMA.STATISTICS`, `INFORMATION_SCHEMA.TABLE_CONSTRAINTS`, and `INFORMATION_SCHEMA.KEY_COLUMN_USAGE`, and enforced for existing-row validation, `INSERT ... VALUES`, `INSERT ... SET`, `INSERT IGNORE ... VALUES` / `SET`, and single-assignment `UPDATE`. Multiple `NULL` values are allowed. No `ALTER TABLE ADD/RENAME UNIQUE`, composite indexes, non-ASCII string key values, prefix lengths, descending key parts, functional key parts, named constraints, visibility toggles, comments, parser options, or optimizer-use guarantees |
| Nonunique indexes | 🟡 | Limited table-level `KEY` / `INDEX [name] (column)` definitions inside `CREATE TABLE` plus limited single-action `ALTER TABLE table_name ADD INDEX\|KEY [name] (column)`, standalone `CREATE INDEX index_name ON table_name (column_name)`, and `ALTER TABLE table_name DROP INDEX\|KEY index_name` for supported descriptor-owned secondary indexes on persistent base tables, including integer-family, exact `DECIMAL`, canonical `DATE`, canonical `DATETIME`, canonical `TIMESTAMP`, and `CHAR(1..255)` / `VARCHAR(1..255)` descriptors. The descriptor is backed by a generated SQLite index, cloned by `CREATE TABLE ... LIKE`, omitted by `CREATE TABLE ... SELECT`, rendered in `SHOW COLUMNS`, `SHOW CREATE TABLE`, `SHOW INDEX`, and limited `INFORMATION_SCHEMA.STATISTICS`. No standalone `DROP INDEX`, `ALTER TABLE RENAME INDEX`, fulltext/spatial indexes, composite indexes, prefix lengths, descending key parts, functional key parts, visibility toggles, comments, parser options, or optimizer-use guarantees |
| Descending indexes | ❌ | DESC key-part syntax and ordering semantics |
| Prefix indexes | ❌ | Prefix length parsing, byte/character semantics, and limits |
| Functional key parts | ❌ | Expression key parts and metadata |
| Multi-valued indexes | ❌ | JSON array index behavior |
| FULLTEXT indexes | ❌ | Parser options and MATCH metadata |
| SPATIAL indexes | ❌ | Geometry column requirements and spatial metadata |
| Foreign keys | ❌ | Cascades, checks, metadata |
| Foreign key checks variable | 🟡 | Limited scalar `@@foreign_key_checks` reads report fixed enabled value `1`; no mutable checking state, foreign key DDL, enforcement, cascades, metadata, or dependency checks |
| Unique checks variable | 🟡 | Limited scalar `@@unique_checks` reads report fixed enabled value `1`; no mutable checking state, toggleable enforcement, optimizer effects, or import optimizations |
| CHECK constraints | ❌ | Expression validation, enforcement, names, and metadata |
| Constraint naming | ❌ | Names, scope, SHOW CREATE |
| CREATE INDEX options | ❌ | ALGORITHM, LOCK, visibility |
| `ADD PRIMARY KEY` | 🟡 | Limited `ALTER TABLE table_name ADD PRIMARY KEY (column_name[, ...])` for persistent base tables and existing unqualified integer-family descriptor columns, plus single-column ASCII-valued `CHAR(1..255)` / `VARCHAR(1..255)` descriptors; validates existing rows for `NULL` with `1138 / 22004`, duplicate key tuples with `1062 / 23000`, and supported ASCII string-key values, reports zero affected rows and warnings, and updates ordered descriptor/physical index metadata atomically. No named constraints, composite string keys, non-ASCII string key values, key options, multi-action `ALTER`, generated invisible keys, or auto-increment conversion |
| `DROP PRIMARY KEY` | 🟡 | Limited single-action `ALTER TABLE table_name DROP PRIMARY KEY` for persistent base tables; deletes primary-key descriptors and the generated SQLite unique index atomically, preserves rows, columns, and supported secondary indexes, leaves former key columns `NOT NULL`, reports the table's current row count, and rejects tables without a primary key or drops that would leave an auto-increment column unindexed. No `DROP CONSTRAINT`, `DROP INDEX PRIMARY`, multi-action `ALTER`, temporary tables, views, algorithms, locks, foreign keys, cascades, triggers, or implicit-commit emulation |
| `ADD UNIQUE` | ❌ | Unique index addition and duplicate validation |
| `ADD INDEX` / `ADD KEY` | 🟡 | Limited single-action `ALTER TABLE table_name ADD INDEX\|KEY [index_name] (column_name)` for persistent base tables and one existing unqualified supported non-`TEXT` descriptor column; creates secondary-index and index-column descriptors plus one generated SQLite index, supports omitted-name generation with `_2`, `_3`, ... suffixes, reports zero affected rows/warnings, and updates descriptor-driven `SHOW`, `CREATE TABLE ... LIKE`, limited `INFORMATION_SCHEMA.STATISTICS`, DML, and auto-increment key checks. No `ADD UNIQUE`, multi-action `ALTER`, composite/prefix/descending/functional/table-qualified key parts, index options, comments, visibility, temporary tables, views, or optimizer guarantees |
| `ADD FULLTEXT` | ❌ | Full-text index addition |
| `ADD SPATIAL` | ❌ | Spatial index addition |
| `DROP INDEX` / `DROP KEY` | 🟡 | Limited single-action `ALTER TABLE table_name DROP INDEX\|KEY index_name` for descriptor-owned unique and nonunique secondary indexes on persistent base tables; deletes index descriptors and the generated SQLite index atomically, preserves rows, columns, primary keys, other secondary indexes, and allowed auto-increment descriptors, reports zero affected rows/warnings, and updates descriptor-driven `SHOW`, `CREATE TABLE ... LIKE`, limited `INFORMATION_SCHEMA`, and DML behavior. No standalone `DROP INDEX ... ON`, primary-key drops through `DROP INDEX`, multi-action `ALTER`, temporary tables, views, algorithms, locks, foreign-key dependency checks, cascades, triggers, or optimizer guarantees |
| `RENAME INDEX` / `RENAME KEY` | ❌ | Index rename semantics |
| `ALTER INDEX VISIBLE` / `INVISIBLE` | ❌ | Index visibility metadata and optimizer behavior |
| `ADD CONSTRAINT CHECK` | ❌ | Check constraint addition and validation |
| `DROP CHECK` | ❌ | Check constraint removal |
| `ALTER CHECK ENFORCED` / `NOT ENFORCED` | ❌ | Check enforcement toggling |
| `ADD CONSTRAINT FOREIGN KEY` | ❌ | Foreign key addition, validation, indexes, and actions |
| `DROP FOREIGN KEY` | ❌ | Foreign key removal and metadata cleanup |
| `DISABLE KEYS` / `ENABLE KEYS` | ❌ | MyISAM-style key maintenance syntax, diagnostics |
