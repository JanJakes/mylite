# SQL indexes and constraints

Standalone index statements plus index, key, constraint, foreign-key, and check DDL details.

## Statement surface

| Feature | Status | Notes |
| --- | --- | --- |
| `CREATE INDEX` | 🟡 | Limited standalone `CREATE INDEX index_name ON table_name (key_part[, ...])` for persistent base tables and shadowing session temporary tables with unqualified descriptor columns, including nonunique composite indexes, full-column `BINARY` / `VARBINARY` key parts, nonunique character prefix parts on `CHAR`, `VARCHAR`, and bare `TEXT` family descriptors, and nonunique binary prefix parts on `BINARY`, `VARBINARY`, and BLOB-family descriptors within current type-family and 3072-byte key-length envelopes. `CREATE UNIQUE INDEX` supports one or more full existing supported descriptor columns including `BINARY` / `VARBINARY`, plus string prefix keys on `CHAR`, `VARCHAR`, and bare `TEXT` family descriptors and binary prefix keys on `BINARY`, `VARBINARY`, and BLOB-family descriptors, including composite prefix key parts. Supported non-spatial key parts may specify `ASC` or `DESC`; omitted direction is ascending. Non-fulltext/non-spatial standalone indexes admit `USING BTREE`, legacy `TYPE btree` placement before or after the indexed table, `USING HASH` without ordered key parts, ignored `KEY_BLOCK_SIZE`, `COMMENT '...'`, and `VISIBLE` / `INVISIBLE`; `USING BTREE` and legacy `TYPE btree` are preserved as BTREE metadata for `SHOW CREATE TABLE`, while `USING HASH` stores BTREE metadata and reports MySQL note `3502`. Persistent creates descriptor-owned durable index metadata plus one generated SQLite index, validates existing duplicate rows for unique indexes, and updates descriptor-driven `SHOW`, `CREATE TABLE ... LIKE`, limited `INFORMATION_SCHEMA`, DML duplicate checks, and `ALTER TABLE ... DROP INDEX\|KEY` / standalone `DROP INDEX`; temporary creates mutate only connection-local temporary descriptors, report the current temporary table row count, render through `SHOW`, enforce supported unique indexes for DML, and remain omitted from `INFORMATION_SCHEMA`. `CREATE FULLTEXT INDEX` is metadata-only for supported persistent fulltext columns, admits `COMMENT` and visibility options but not `USING`, while `WITH PARSER parser_name` reaches an unsupported utility diagnostic rather than an accidental syntax error, emits warning 124 only when first introducing a table's fulltext document-id state, and creates no SQLite index; temporary fulltext creation returns MySQL-compatible error 1796. `CREATE SPATIAL INDEX` is metadata-only for one existing persistent `NOT NULL` spatial descriptor column, admits `COMMENT` and visibility options but not `USING`, emits warning 3674 for the current no-SRID descriptor subset, and creates no SQLite index; temporary spatial creation is deferred. Ordinary nonunique `CREATE INDEX` with omitted type or `USING RTREE` over one supported persistent spatial column normalizes to the same metadata-only spatial descriptor; `USING BTREE` / `USING HASH` over spatial columns is rejected with MySQL's spatial-index-type diagnostic. No omitted names, `IF NOT EXISTS`, primary-key creation, unique spatial indexes, functional/table-qualified key parts, algorithms, locks, views, per-index key-block storage semantics, temporary fulltext or spatial indexes, spatial search, fulltext parser plugins, or optimizer guarantees |
| `DROP INDEX` | 🟡 | Limited standalone `DROP INDEX index_name ON table_name` for descriptor-owned unique, nonunique secondary, metadata-only full-text, and metadata-only spatial indexes on persistent base tables, plus supported unique and nonunique secondary indexes on shadowing session temporary tables; persistent drops delete descriptors and the generated SQLite index when one exists, preserve rows, columns, primary keys, other supported secondary indexes, and allowed auto-increment descriptors, report zero affected rows/warnings, reject drops of indexes used by supported foreign-key descriptors, and update descriptor-driven `SHOW`, `CREATE TABLE ... LIKE`, limited `INFORMATION_SCHEMA`, and DML behavior. Temporary drops remove only connection-local descriptors, drop the generated temporary SQLite index, report the current temporary table row count, update `SHOW` and DML behavior, and remain omitted from `INFORMATION_SCHEMA`. No standalone `DROP KEY`, `IF EXISTS`, primary-key drops through ``DROP INDEX `PRIMARY` ON ...``, algorithms, locks, views, cascades, triggers, or optimizer guarantees |
| Multi-action `ALTER TABLE` index actions | 🟡 | Limited persistent base-table multi-action lists can combine current no-warning ordinary `ADD INDEX` / `ADD KEY`, `ADD UNIQUE` / named unique constraint, `DROP INDEX` / `DROP KEY`, `ADD PRIMARY KEY`, and `DROP PRIMARY KEY` subsets with supported no-warning `ADD COLUMN` and catalog default actions inside one atomic catalog mutation. Later actions resolve descriptor changes from earlier actions in the same statement, failed later actions roll the full list back, and final-state validation keeps `AUTO_INCREMENT` columns indexed when a primary key is dropped and a supporting key is added in the same statement. Limited leading or trailing comma-separated `ALGORITHM` / `LOCK` options are admitted for supported action lists. No temporary-table multi-action index DDL, warning-producing fulltext/spatial/hash-index/primary-key adds, foreign-key actions, check actions, mixed table-option actions inside an action list, or broader online-DDL semantics |
| `CACHE INDEX` | ❌ | MyISAM key cache assignment syntax |
| `LOAD INDEX INTO CACHE` | ❌ | MyISAM index preload syntax |

| Feature | Status | Notes |

| Primary keys | 🟡 | Limited descriptor-owned primary keys declared in `CREATE TABLE`, including bare `CONSTRAINT PRIMARY KEY`, or added later with `ALTER TABLE ... ADD PRIMARY KEY (column[, ...])` or bare `ALTER TABLE ... ADD CONSTRAINT PRIMARY KEY (column[, ...])`, and keys removed with `ALTER TABLE ... DROP PRIMARY KEY`. Supported key parts are integer-family descriptors and ASCII-valued `CHAR(1..255)` / `VARCHAR(1..255)` descriptors, including table-level composite integer, string, and mixed keys, with optional `ASC` / `DESC` direction metadata on table-level and alter-added parts. Inline column `KEY` is accepted as the same single-column primary-key attribute as `PRIMARY KEY`. Creation and add-primary-key forms admit optional primary-key index names that are ignored like MySQL, limited `USING BTREE`, `USING HASH` without ordered key parts, `COMMENT '...'`, `VISIBLE`, and repeated visibility options; final effective `INVISIBLE` is rejected for primary keys, `USING BTREE` is preserved for `SHOW CREATE TABLE`, and `USING HASH` stores ordinary BTREE metadata and reports note `3502`. Added keys validate existing rows for `NULL`, duplicate key tuples, supported ASCII string-key values, and the 3072-byte aggregate key-length envelope, make every key-part descriptor column `NOT NULL`, preserve supported defaults and secondary indexes, and create a generated SQLite unique index with the MyLite `utf8mb4_0900_ai_ci` ASCII collation annotation for string key parts. Dropped keys remove the descriptor rows and generated physical index, preserve rows, column descriptors, and supported secondary indexes, leave former key columns `NOT NULL`, report the current table row count, reject drops when the key is referenced by a supported foreign key, and keep an auto-increment column only if a supported secondary index still indexes it. Existing DML enforces duplicate keys for current `INSERT ... VALUES` / `INSERT ... SET`, `INSERT IGNORE`, the current `INSERT ... ON DUPLICATE KEY UPDATE` subset including non-auto key-column duplicate assignments, and single-assignment `UPDATE`; supported integer primary keys may serve as one-column or composite FK parent keys; `CREATE TABLE ... LIKE`, `SHOW COLUMNS` / `SHOW INDEX` / `SHOW CREATE TABLE`, and limited `INFORMATION_SCHEMA.COLUMNS.COLUMN_KEY`, `INFORMATION_SCHEMA.STATISTICS`, `INFORMATION_SCHEMA.TABLE_CONSTRAINTS`, and `INFORMATION_SCHEMA.KEY_COLUMN_USAGE` metadata observe the descriptor. Primary prefix parts are parsed but rejected before catalog mutation; no primary prefix enforcement, inline column primary-key index options, non-ASCII string key values, named primary-key constraints, auto-increment conversion, or optimizer/index-use guarantees |
| Unique indexes | 🟡 | Limited descriptor-owned unique indexes declared inside `CREATE TABLE` with inline `UNIQUE` / `UNIQUE KEY`, table-level `UNIQUE [KEY\|INDEX] [name] (column[, ...])`, named table-level `CONSTRAINT name UNIQUE [KEY\|INDEX] (key_part[, ...])` forms that store the visible unique-index name in the existing secondary-index descriptor, standalone `CREATE UNIQUE INDEX index_name ON table_name (column_name[, ...])`, single-action `ALTER TABLE table_name ADD UNIQUE [INDEX\|KEY] [name] (column_name[, ...])`, or single-action `ALTER TABLE table_name ADD CONSTRAINT [symbol] UNIQUE [INDEX\|KEY] [name] (column_name[, ...])` on integer-family, exact `DECIMAL`, canonical `YEAR`, canonical `DATE`, canonical `TIME`, canonical `DATETIME`, canonical `TIMESTAMP`, ASCII-valued `CHAR(1..255)` / `VARCHAR(1..255)`, and full `BINARY` / `VARBINARY` descriptor columns; post-create standalone and ALTER add/drop forms also operate on shadowing session temporary tables for this subset. String prefix unique indexes including composite prefix key parts are supported on `CHAR`, `VARCHAR`, and bare `TEXT` family descriptors; binary prefix unique indexes including composite prefix key parts are supported on `BINARY`, `VARBINARY`, and BLOB-family descriptors. Supported table-level, named table-level, alter-added, and standalone key parts may specify `ASC` or `DESC`; omitted direction is ascending. Creation forms admit limited `USING BTREE`, `USING HASH` without ordered key parts, `COMMENT '...'`, and `VISIBLE` / `INVISIBLE` index options; `USING HASH` stores BTREE metadata and reports note `3502`. The descriptor is backed by a generated SQLite unique index, using the MyLite `utf8mb4_0900_ai_ci` ASCII collation annotation for string key parts and prefix expressions, cloned by `CREATE TABLE ... LIKE`, omitted by `CREATE TABLE ... SELECT`, removable with limited `ALTER TABLE ... DROP INDEX\|KEY` or standalone `DROP INDEX`, visibility-toggleable with limited `ALTER TABLE ... ALTER INDEX` for persistent tables, rendered in `SHOW COLUMNS`, `SHOW CREATE TABLE`, `SHOW INDEX`, and limited persistent-table `INFORMATION_SCHEMA.STATISTICS`, `INFORMATION_SCHEMA.TABLE_CONSTRAINTS`, and `INFORMATION_SCHEMA.KEY_COLUMN_USAGE`, and enforced for existing-row validation, `INSERT ... VALUES`, `INSERT ... SET`, `INSERT IGNORE ... VALUES` / `SET`, the current `INSERT ... ON DUPLICATE KEY UPDATE` subset including composite/prefix unique keys and non-auto key-column duplicate assignments, and single-assignment `UPDATE`. Temporary post-create add/drop mutates connection-local descriptors and reports the current temporary row count. Multiple `NULL` values are allowed. No `ALTER TABLE ... RENAME UNIQUE`, non-ASCII string key values, full-column BLOB-family keys, primary prefix indexes, functional key parts, separate unique-constraint descriptors, redundant-index warnings, or optimizer-use guarantees |
| Nonunique indexes | 🟡 | Limited table-level `KEY` / `INDEX [name] (key_part[, ...])` definitions inside `CREATE TABLE` plus limited single-action `ALTER TABLE table_name ADD INDEX\|KEY [name] (key_part[, ...])`, standalone `CREATE INDEX index_name ON table_name (key_part[, ...])`, `ALTER TABLE table_name DROP INDEX\|KEY index_name`, standalone `DROP INDEX index_name ON table_name`, catalog-only `ALTER TABLE table_name RENAME INDEX\|KEY old_name TO new_name`, and catalog-only `ALTER TABLE table_name ALTER INDEX index_name VISIBLE\|INVISIBLE` for supported descriptor-owned secondary indexes on persistent base tables; standalone create/drop and ALTER add/drop forms also operate on shadowing session temporary tables for the supported ordinary secondary subset. Supported non-spatial key parts may specify `ASC` or `DESC`; omitted direction is ascending.
