# SQL table DDL

Table lifecycle, table-specific DDL, CREATE TABLE options, and ALTER TABLE
actions.

| `DROP TABLE` | 🟡 | Limited persistent base-table drop with comma-separated target lists and optional `IF EXISTS`; missing-table and missing-explicit-schema `IF EXISTS` forms are no-ops with `Note 1051`, duplicate targets fail before mutation, and non-`IF EXISTS` missing targets fail atomically; no `TEMPORARY`, `RESTRICT`, or `CASCADE` |
| `RENAME TABLE` | 🟡 | Limited persistent base-table rename with one or more left-to-right pairs from `baseline-table-rename-lifecycle` and `baseline-multi-table-rename-lifecycle`, including unqualified, schema-qualified, and cross-schema names plus statement rollback on pair failure; no temporary tables, views, triggers, metadata locks, foreign keys, or privilege semantics |
| `TRUNCATE TABLE` | 🟡 | Limited persistent base-table `TRUNCATE [TABLE] table_name` for unqualified and schema-qualified descriptor targets; empties physical rows, preserves descriptors, resets the current auto-increment counter subset to `1`, and reports zero affected rows; no implicit commits, temporary tables, partitions, foreign keys, triggers, locks, privileges, or physical storage rebuild semantics |
| Atomic DDL | 🟡 | Catalog descriptor rows and generated physical SQLite table/index changes commit or roll back atomically for the limited create/create-like/drop/rename/truncate and single-action alter rename/add-column/add-primary-key/add-index/drop-primary-key/drop-index/drop-column/rename-column/modify-column/change-column/order-by/force subsets only |
| Implicit commit boundaries | ❌ | Implicit commit boundaries |
| `IMPORT TABLE` | ❌ | Transportable tablespace import syntax, diagnostics |

## ALTER TABLE actions

| Feature | Status | Notes |
| --- | --- | --- |
| `ADD COLUMN` | 🟡 | Limited append-only `ALTER TABLE table_name ADD [COLUMN] column_name column_type [NULL\|NOT NULL] [DEFAULT NULL\|DEFAULT integer_literal\|DEFAULT decimal_literal\|DEFAULT TRUE\|DEFAULT FALSE\|DEFAULT canonical_date_string\|DEFAULT canonical_datetime_string\|DEFAULT canonical_timestamp_string\|DEFAULT string_literal_for_CHAR_or_VARCHAR]` for persistent base tables; supports `TINYINT`, `SMALLINT`, `MEDIUMINT`, `INT`/`INTEGER`, `BIGINT`, `INT1`/`INT2`/`INT3`/`INT4`/`INT8` aliases, bare `BOOL`/`BOOLEAN` aliases, exact `DECIMAL`/`DEC`/`NUMERIC`/`FIXED`, canonical `DATE`, canonical `DATETIME`, canonical `TIMESTAMP`, limited bare `CHAR`, `CHAR(0..255)`, `CHARACTER`, `CHARACTER(0..255)`, `VARCHAR(0..16383)`, `CHARACTER VARYING(0..16383)`, and `CHAR VARYING(0..16383)`, and bare `TEXT` family types, with optional deprecated display width `0..255` before optional single `SIGNED` or `UNSIGNED` for integer-family and `INT*` aliases and optional deprecated `UNSIGNED` for decimal descriptors; existing rows backfill descriptor defaults, nullable no-default columns backfill `NULL`, integer and decimal not-null no-default columns backfill target zero values, `DATE NOT NULL` and `DATETIME NOT NULL` no-default columns succeed only for empty tables and otherwise fail on the implicit zero temporal value under the current strict mode, `TIMESTAMP NOT NULL` no-default columns backfill `0000-00-00 00:00:00` even for existing rows in the fixed-UTC baseline, and string not-null no-default columns backfill empty strings while catalog metadata remains no-explicit-default; widened `VARCHAR` add-column definitions are checked against MyLite's descriptor-owned MySQL row-size envelope; no positioning, multiple actions, parenthesized lists, `TEXT`-family string defaults, warning-producing overlength string-default truncation, expression defaults, generated/invisible/auto-increment columns, added primary keys or other keys, constraints, algorithms, locks, temporary tables, or views |
| `ADD PRIMARY KEY` | 🟡 | Limited single-action `ALTER TABLE table_name ADD PRIMARY KEY (column_name[, ...])` for persistent base tables and existing unqualified integer-family descriptor columns plus single-column ASCII `CHAR(1..255)` / `VARCHAR(1..255)` descriptor columns. Existing rows must contain no `NULL` values in any key part, no duplicate key tuples, and no unsupported string-key values; success reports zero affected rows/warnings, makes every key-part descriptor column `NOT NULL`, normalizes implicit/explicit `NULL` defaults to no explicit default, preserves supported defaults and secondary indexes, creates one generated SQLite unique index, and drives existing DML, `SHOW`, `CREATE TABLE ... LIKE`, and limited `INFORMATION_SCHEMA` metadata from ordered descriptors. No `ADD CONSTRAINT`, composite string primary keys, non-ASCII string key values, key options, multi-action `ALTER`, auto-increment conversion, algorithms, locks, temporary tables, or views |
| `ADD UNIQUE` | 🟡 | Limited single-action `ALTER TABLE table_name ADD UNIQUE [INDEX\|KEY] [index_name] (column_name)` for persistent base tables and one existing unqualified supported descriptor column, including integer-family, exact `DECIMAL`, canonical `DATE`, canonical `DATETIME`, canonical `TIMESTAMP`, and ASCII `CHAR(1..255)` / `VARCHAR(1..255)` descriptors. Existing non-`NULL` duplicate values fail before mutation, duplicate `NULL` values are allowed, success reports zero affected rows/warnings for non-redundant supported forms, creates descriptor-owned unique secondary-index metadata plus one generated SQLite unique index, supports omitted-name suffixing for name collisions, preserves rows and column descriptors, and is visible to `SHOW`, `CREATE TABLE ... LIKE`, limited `INFORMATION_SCHEMA`, DML duplicate checks, `ALTER TABLE ... DROP INDEX\|KEY`, and standalone `DROP INDEX`. No `ADD CONSTRAINT UNIQUE`, multiple actions, composite/prefix/descending/functional/table-qualified key parts, index options, comments, visibility, redundant-index warnings, fulltext/spatial indexes, algorithms, locks, temporary tables, or views |
| `ADD INDEX` / `ADD KEY` | 🟡 | Limited single-action `ALTER TABLE table_name ADD INDEX\|KEY [index_name] (column_name)` for persistent base tables and one existing unqualified supported non-`TEXT` descriptor column, including integer-family, exact `DECIMAL`, canonical `DATE`, canonical `DATETIME`, canonical `TIMESTAMP`, and `CHAR(1..255)` / `VARCHAR(1..255)` descriptors. Success reports zero affected rows/warnings, creates descriptor-owned nonunique secondary-index metadata plus one generated SQLite index, supports omitted-name suffixing, preserves rows and column descriptors, and is visible to `SHOW`, `CREATE TABLE ... LIKE`, limited `INFORMATION_SCHEMA.STATISTICS`, DML, and auto-increment key checks. No multiple actions, composite/prefix/descending/functional/table-qualified key parts, index options, comments, visibility, fulltext/spatial indexes, algorithms, locks, temporary tables, or views |
| `DROP PRIMARY KEY` | 🟡 | Limited single-action `ALTER TABLE table_name DROP PRIMARY KEY` for persistent base tables. Success deletes primary-key descriptor rows and the generated SQLite unique index, preserves row values, column descriptors, supported secondary indexes, and allowed auto-increment descriptors, leaves former key columns `NOT NULL`, updates descriptor-driven DML, `SHOW`, `CREATE TABLE ... LIKE`, and limited `INFORMATION_SCHEMA` metadata, and reports the current table row count. Tables without a primary key fail, and dropping the only key on an auto-increment column is rejected; no `DROP CONSTRAINT`, `DROP INDEX PRIMARY`, multi-action `ALTER`, algorithms, locks, temporary tables, views, foreign keys, triggers, cascades, or implicit-commit emulation |
| `DROP INDEX` / `DROP KEY` | 🟡 | Limited single-action `ALTER TABLE table_name DROP INDEX\|KEY index_name` for descriptor-owned unique and nonunique secondary indexes on persistent base tables. Success deletes secondary-index descriptor rows and the generated SQLite index, preserves row values, column descriptors, primary-key descriptors, other supported secondary indexes, and allowed auto-increment descriptors, updates descriptor-driven DML, `SHOW`, `CREATE TABLE ... LIKE`, and limited `INFORMATION_SCHEMA` metadata, and reports zero affected rows/warnings. Unknown indexes fail with MySQL-compatible `1091`, and dropping the last key on an auto-increment column is rejected; no primary-key drops through `DROP INDEX`, multi-action `ALTER`, algorithms, locks, temporary tables, views, foreign keys, triggers, cascades, or implicit-commit emulation |
| `AUTO_INCREMENT` table option | 🟡 | Limited single-action `ALTER TABLE table_name AUTO_INCREMENT [=] nonnegative_integer_literal` for persistent base tables. For tables with the current supported auto-increment descriptor, MyLite updates the durable next counter to the greater of the requested value and the next value after the current maximum row value; `AUTO_INCREMENT=0` normalizes to the lower bound, lowered counters after deletes are supported, generated inserts and metadata observe the new counter, and tables without an auto-increment column are accepted no-ops. No signed, decimal, string, hex, bit, expression, parameter, duplicate-option, or multi-action forms; no add/drop/modify of the auto-increment column attribute, algorithms, locks, temporary tables, or views |
| `DROP COLUMN` | 🟡 | Limited single-column `ALTER TABLE table_name DROP [COLUMN] column_name` for persistent base tables; removes the MyLite descriptor column, compacts later descriptor ordinals, preserves remaining row values, and emits MySQL-compatible diagnostics for unknown columns, attempts to drop the last column, attempts to drop the last visible column when other columns are invisible, and attempts to drop the current primary-key column; no multiple actions, table-qualified drop targets, key dependency updates, constraints, algorithms, locks, temporary tables, or views |
| `RENAME COLUMN` | 🟡 | Limited single-action `ALTER TABLE table_name RENAME COLUMN old_col TO new_col` for persistent base tables; preserves column id, ordinal position, integer type, nullability, and row values, supports exact same-name no-op and case-only spelling changes, and rejects duplicate, unknown, and current primary-key columns until key-aware column rename is specified; no multiple actions, table-qualified column names, type changes, dependency updates, algorithms, locks, temporary tables, or views |
| `CHANGE COLUMN` | 🟡 | Limited single-action `ALTER TABLE table_name CHANGE [COLUMN] old_col new_col integer_type [NULL\|NOT NULL] [DEFAULT NULL\|DEFAULT integer_literal\|DEFAULT TRUE\|DEFAULT FALSE]` for persistent base tables without primary-key or secondary-index descriptors; supports `TINYINT`, `SMALLINT`, `MEDIUMINT`, `INT`/`INTEGER`, `BIGINT`, `INT1`/`INT2`/`INT3`/`INT4`/`INT8` aliases, and bare `BOOL`/`BOOLEAN` aliases with optional deprecated display width `0..255` before optional single `SIGNED` or `UNSIGNED` for integer-family and `INT*` aliases, preserves column id and ordinal position, replaces name/type/nullability/default from the replacement definition, treats omitted nullability as nullable, makes the target visible because visibility attributes are not admitted, supports exact same-definition no-op and case-only spelling changes, validates existing integer/`NULL` row values inside the catalog mutation before descriptor replacement, keeps display-width-only, bool-alias range-equivalent, and default-only changes metadata-only except for physical column renames, and rebuilds descriptor-backed physical tables when type range or nullability changes; rebuilds currently require at least one unshadowed SQLite rowid alias; no positioning, non-integer types, multiple actions, table-qualified column names, generated/invisible/auto-increment columns, added primary keys or other keys, constraints, dependency checks, algorithms, locks, temporary tables, or views |
| `MODIFY COLUMN` | 🟡 | Limited single-action `ALTER TABLE table_name MODIFY [COLUMN] column_name integer_type [NULL\|NOT NULL] [DEFAULT NULL\|DEFAULT integer_literal\|DEFAULT TRUE\|DEFAULT FALSE]` for persistent base tables without primary-key or secondary-index descriptors; supports `TINYINT`, `SMALLINT`, `MEDIUMINT`, `INT`/`INTEGER`, `BIGINT`, `INT1`/`INT2`/`INT3`/`INT4`/`INT8` aliases, and bare `BOOL`/`BOOLEAN` aliases with optional deprecated display width `0..255` before optional single `SIGNED` or `UNSIGNED` for integer-family and `INT*` aliases, preserves column id and ordinal position, replaces nullability/default exactly as specified, makes the target visible because visibility attributes are not admitted, supports exact same-definition no-op and case-only spelling changes, validates existing integer/`NULL` row values inside the catalog mutation before descriptor replacement, keeps display-width-only, bool-alias range-equivalent, and default-only changes metadata-only, and rebuilds descriptor-backed physical tables when type range or nullability changes; rebuilds currently require at least one unshadowed SQLite rowid alias; no positioning, non-integer types, multiple actions, table-qualified column names, generated/invisible/auto-increment columns, added primary keys or other keys, constraints, dependency checks, algorithms, locks, temporary tables, or views |
| `ALTER COLUMN SET DEFAULT` | 🟡 | Limited catalog-only `ALTER TABLE table_name ALTER [COLUMN] column_name SET DEFAULT value` for persistent base tables and one unqualified integer-family, decimal, `CHAR`, `VARCHAR`, `DATE`, `DATETIME`, or `TIMESTAMP` descriptor column; `value` may be `NULL` for nullable columns, an in-range decimal integer literal with optional unary sign, `TRUE`, or `FALSE` for integer descriptors, a compatible fixed decimal literal for decimal descriptors, a string literal for `CHAR`/`VARCHAR` descriptors, a canonical date-string literal for `DATE` descriptors, a canonical datetime-string literal for `DATETIME` descriptors, or a canonical timestamp-string literal for `TIMESTAMP` descriptors; preserves existing row values and physical SQLite schema, reports zero affected rows and warnings, and updates descriptor defaults for later omitted-column inserts; defaults on `AUTO_INCREMENT` columns are hidden from `SHOW COLUMNS` / `SHOW CREATE TABLE` like MySQL, while ordinary column defaults render normally; no expression defaults, `TEXT`-family string defaults, warning-producing overlength string-default truncation, float/hex/bit defaults, temporal function defaults, table-qualified columns, multiple actions, temporary tables, or views |
| `ALTER COLUMN DROP DEFAULT` | 🟡 | Limited catalog-only `ALTER TABLE table_name ALTER [COLUMN] column_name DROP DEFAULT` for persistent base tables and one unqualified descriptor column; preserves existing row values and physical SQLite schema, reports zero affected rows and warnings, stores a dropped-default descriptor state distinct from implicit nullable `DEFAULT NULL`, makes later omitted-column inserts fail, and renders MySQL-compatible `SHOW COLUMNS` / `SHOW CREATE TABLE` metadata; no table-qualified columns, multiple actions, temporary tables, or views |
| `ALTER COLUMN SET VISIBLE` / `SET INVISIBLE` | 🟡 | Limited catalog-only `ALTER TABLE table_name ALTER [COLUMN] column_name SET VISIBLE\|INVISIBLE` for persistent base tables and one unqualified descriptor column; preserves row values and physical SQLite schema, reports zero affected rows and warnings, prevents making every column invisible with MySQL error 4028, and drives `SELECT *`, implicit insert mapping, `SHOW COLUMNS`, and `SHOW CREATE TABLE`; no table-qualified columns, multiple actions, column-definition visibility syntax, generated invisible primary keys, protocol flags, temporary tables, or views |
| `RENAME TO` | 🟡 | Limited single-action persistent base-table `ALTER TABLE ... | `ORDER BY` | 🟡 | Limited single-action `ALTER TABLE table_name ORDER BY column_name [ASC\|DESC][, ...]` for persistent base tables without primary-key or secondary-index descriptors; resolves unqualified, target-table-qualified, and target-schema-table-qualified descriptor columns, rebuilds the physical SQLite table with `INSERT INTO temp SELECT ... | `CONVERT TO CHARACTER SET` | ❌ | Column/table charset and collation conversion semantics |
| `DEFAULT CHARACTER SET` / `COLLATE` | 🟡 | Limited fixed metadata no-op `ALTER TABLE table_name [DEFAULT] CHARSET` / `CHARACTER SET utf8mb4` and `ALTER TABLE table_name [DEFAULT] COLLATE utf8mb4_0900_ai_ci` for persistent base tables; validates the fixed baseline names, preserves descriptors and rows, and reports zero affected rows/warnings; no conversion, non-default charsets/collations, descriptor charset metadata, collation comparison semantics, multiple actions, temporary tables, views, or full charset/collation catalogs |
| `FORCE` | 🟡 | Limited single-action `ALTER TABLE table_name FORCE` for persistent base tables without primary-key or secondary-index descriptors; performs a descriptor-driven SQLite-side physical rebuild, preserves row values and logical descriptors, reports zero affected rows/warnings, and increments only SQLite schema generation; no temporary tables, repeated or mixed ALTER actions, storage-engine defragmentation guarantees, algorithms, locks, indexes, implicit commits, or privileges |
