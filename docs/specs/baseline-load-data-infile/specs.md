# Baseline Load Data Infile

## Goal

Add a narrow server-side text import path:

```sql
LOAD DATA INFILE 'path' INTO TABLE table_name
    [IGNORE row_count LINES]
    [(column_name[, column_name] ...)]
```

This phase imports tab-separated, newline-terminated files into descriptor-owned
persistent or shadowing session-temporary base tables. It deliberately reuses
MyLite's existing insert/default/type/constraint execution path instead of
letting SQLite interpret MySQL import syntax or MySQL column descriptors.

It is not a general `LOAD DATA` implementation. `LOCAL`, duplicate-handling
modifiers, custom field/line clauses, user variables, `SET` tails, character-set
clauses, partitions, and XML import remain deferred.

## Sources And Evidence

- Official MySQL 8.4 Reference Manual, `LOAD DATA` statement:
  <https://dev.mysql.com/doc/refman/8.4/en/load-data.html>
- Existing MyLite insert, descriptor, diagnostics, storage, and statement
  transaction behavior.
- Observed MySQL 8.4.9 runtime behavior, captured by
  `packages/libmylite/tests/mysql_baseline_load_data_infile_expectations.sh`.

This specification is independently authored from official documentation,
observed MySQL 8.4.9 behavior, public SQLite APIs, and existing MyLite code. It
does not copy MySQL, MariaDB, Percona, SQLite implementation internals, or
restrictively licensed sources.

## MySQL 8.4.9 Runtime Observations

Runtime probes establish the behavior used by this baseline:

- A server-side `LOAD DATA INFILE` statement reads a file on the server host.
  MyLite runs embedded in the application process, so the "server host" is the
  current process host.
- The filename is a SQL string literal.
- With default field and line settings, fields are separated by tab bytes and
  rows are separated by linefeed bytes.
- With the default escape character, the field value `\N` is read as SQL
  `NULL`. Empty fields are not `NULL`.
- With no column list, input fields map to visible table columns in descriptor
  order. With a column list, fields map only to the listed columns and omitted
  columns receive descriptor defaults or implicit missing-default handling
  through the normal DML rules.
- `IGNORE n LINES` appears after `INTO TABLE table_name` and before the optional
  column list. It skips complete input rows before column conversion.
- MySQL rejects `IGNORE +1 LINES` and offset-like forms at parse time.
- In restrictive interpretation, too few input fields fail with `1261 / 01000`
  and too many fields fail with `1262 / 01000`.
- In nonrestrictive interpretation, too few fields append one warning `1261`
  per missing target field. Missing fields use MySQL's `LOAD DATA` missing-field
  value policy: nullable columns whose effective default is `NULL` store
  `NULL`, while other admitted columns store the target-family implicit value
  instead of materializing explicit descriptor defaults. Too many fields append
  one warning `1262` for the row and excess fields are ignored.
- Under nonstrict `sql_mode=''`, an empty field for an integer target stores
  `0` and appends warning `1366 / HY000`.
- In strict mode, an empty or invalid integer field fails with
  `1366 / HY000`.
- Assigning `\N` into a nullable target stores SQL `NULL`.
- Assigning `\N` into a `NOT NULL` target fails under restrictive
  interpretation with `1263 / 22004`.
- Missing tables and schemas use the same diagnostics as other DML target
  resolution paths: `1046 / 3D000`, `1049 / 42000`, and `1146 / 42S02`.
- Unknown column-list names fail with `1054 / 42S22`.
- On the local MySQL 8.4.9 runtime used for comparison, `@@local_infile = 0`;
  `LOAD DATA LOCAL INFILE` fails with `3948 / 42000`.
- The comparison runtime has `@@secure_file_priv` set. MyLite does not emulate
  the server privilege system or `secure_file_priv`; this slice reads process
  local paths directly and documents that embedded policy difference.

## Supported SQL

```sql
LOAD DATA INFILE string_literal INTO TABLE table_name
LOAD DATA INFILE string_literal INTO TABLE table_name IGNORE unsigned_integer LINES
LOAD DATA INFILE string_literal INTO TABLE table_name (column_name[, column_name] ...)
LOAD DATA INFILE string_literal INTO TABLE table_name
    IGNORE unsigned_integer LINES
    (column_name[, column_name] ...)
LOAD DATA LOCAL INFILE string_literal INTO TABLE table_name
```

`LOCAL` is parsed only to report MySQL-compatible disabled-local diagnostics for
the current embedded/public API. It does not request bytes from a client.

`table_name` may be unqualified or schema-qualified and follows the current
selected/default schema policy. Explicit `information_schema` and reserved
`_mylite_*` write targets are rejected before any physical SQL is generated by
the same writable-target resolver used by insert/update/delete paths.

The imported file format is limited to the default MySQL text shape:

- tab (`0x09`) separates fields;
- linefeed (`0x0a`) terminates rows;
- a final unterminated row is imported if it contains any field data;
- a trailing linefeed after the last row does not create an extra row;
- the default backslash escape recognizes `\0`, `\b`, `\n`, `\r`, `\t`,
  `\Z`, `\\`, and `\N`;
- `\N` is treated as SQL `NULL` only when read as an escaped field value;
- custom `FIELDS` and `LINES` clauses are deferred.

Admitted target families initially reuse the existing descriptor DML conversion
surface for raw field strings:

- integer-family targets, including unsigned variants within MyLite's current
  signed-64 physical envelope;
- `CHAR`, `VARCHAR`, and baseline `TEXT` family targets;
- canonical and already-relaxed stored `DATE`, `TIME`, `DATETIME`, `TIMESTAMP`,
  and `YEAR` targets through the existing DML temporal conversion helpers;
- `NULL` through `\N`;
- descriptor defaults for omitted columns.

The runtime streams input rows and executes them through one prepared physical
insert statement inside one MyLite statement transaction. It must not materialize
the whole input file as AST rows or as a full in-memory row set.

## Deferred Surface

This slice intentionally does not support:

- `LOW_PRIORITY`, `CONCURRENT`, `REPLACE`, or duplicate-handling `IGNORE`
  modifiers;
- `LOCAL` data transfer;
- `PARTITION`;
- `CHARACTER SET`;
- `FIELDS` or `COLUMNS` clauses, including custom terminators, enclosures, and
  escape characters;
- `LINES STARTING BY` or `LINES TERMINATED BY`;
- fixed-width rows;
- user variables or a `SET` tail;
- expression conversion, functions, defaults written in the file, parameters,
  prepared client streaming, or triggers;
- `LOAD XML`;
- binary/blob-specific import behavior, JSON, spatial values, full enum/set
  semantics, collations beyond existing descriptor conversions, or protocol
  progress metadata;
- MySQL account privileges, `FILE` privilege, or `secure_file_priv`.

Unsupported grammar remains a syntax error unless this specification names a
diagnostic. Unsupported descriptor families fail before mutation with a stable
MyLite unsupported diagnostic.

## Grammar

The Lemon syntax below is MyLite-authored and describes only the admitted
subset:

```lemon
statement(A) ::= load_data_infile_statement(B). { A = B; }

load_data_infile_statement(A) ::=
    LOAD(L) DATA INFILE STRING(F) INTO TABLE table_name(T)
    load_data_ignore_lines_opt(I) insert_column_list_opt(C). {
        A = mylite_sql_parser_make_load_data_infile_statement(
            state, L, F, T, I, C, NULL);
    }

load_data_infile_statement(A) ::=
    LOAD(L) DATA LOCAL(LO) INFILE STRING(F) INTO TABLE table_name(T)
    load_data_ignore_lines_opt(I) insert_column_list_opt(C). {
        A = mylite_sql_parser_make_load_data_infile_statement(
            state, L, F, T, I, C,
            mylite_sql_parser_make_load_data_local_modifier(state, LO));
    }

load_data_ignore_lines_opt(A) ::= . { A = NULL; }
load_data_ignore_lines_opt(A) ::= IGNORE INTEGER(N) LINES. {
    A = mylite_sql_parser_make_literal(
        state, N, MYLITE_SQL_AST_LITERAL_INTEGER);
}
```

The optional column list reuses the insert column-list AST shape. A missing
column list is represented as an empty identifier-list node whose span is empty,
matching existing insert behavior.

## Runtime Ownership Boundaries

- Public API: `mylite_execute()` accepts the statement and returns the existing
  non-row result object. No public ABI changes are required.
- Statement context: owns diagnostics and statement transaction lifetime.
  Successful imports report affected rows through the existing result API and
  warning count through diagnostics.
- Parser/AST: recognizes the narrow syntax and preserves the filename literal,
  target table, optional skipped-line count, optional column list, and optional
  `LOCAL` marker. It does not decode files or descriptors.
- Analyzer/planner/runtime: resolves schema/table/columns from MyLite
  descriptors, validates supported target types, opens the input file, streams
  rows, converts raw fields, and executes physical inserts.
- Catalog module: remains authoritative for logical schemas, tables, columns,
  defaults, keys, foreign keys, and auto-increment counters. `LOAD DATA` may
  advance auto-increment counters and touch table updated-time metadata through
  existing DML paths; it must not mutate schema descriptors, descriptor versions,
  catalog generation, or SQLite schema-generation values.
- Result builder: reports affected inserted rows and no row result set.
- Storage/VFS: `.mylite` file preamble and shifted SQLite payload invariants
  are unchanged. Imported data reaches SQLite only through MyLite-generated
  physical insert SQL against stable physical table names.
- SQLite physical row storage: stores final converted descriptor values.
  SQLite never sees MySQL `LOAD DATA` syntax, raw identifiers from SQL text, or
  logical table names.

## Descriptor Resolution

Target resolution uses the same writable table reference policy as other DML:

- unqualified targets require a selected/default schema;
- schema-qualified targets use the named schema;
- unknown schemas fail with `1049 / 42000`;
- missing default schema fails with `1046 / 3D000`;
- unknown target tables fail with `1146 / 42S02`;
- system/reserved targets fail before physical SQL generation;
- only base-table descriptors are accepted.

Column lists resolve against MyLite column descriptors. Unknown names fail with
`1054 / 42S22`. Duplicate column names fail through the existing duplicate
target diagnostic. Omitted column lists target visible descriptor columns only.
Explicit column lists may name invisible descriptor columns because existing
insert DML does.

Current descriptor name comparison follows existing MyLite identifier matching,
including the current ASCII case-insensitive catalog expectations.

## Field Conversion

Raw fields are parsed from the file and converted before binding:

- `\N` assigns SQL `NULL`.
- Empty fields assign empty strings to string targets, zero to numeric targets,
  and existing zero/adjusted values to temporal targets according to existing
  DML conversion policy. In nonstrict mode, empty `YEAR`, `DATE`, `DATETIME`,
  and `TIMESTAMP` fields store zero temporal values with warnings, while empty
  `TIME` stores `00:00:00` without a warning.
- Non-`NULL` fields are treated as raw text, not SQL source text. They must not
  be wrapped into synthetic SQL string literals.
- Integer-family targets reuse the existing DML string-to-integer prefix scan,
  range clipping, signed/unsigned descriptor ranges, and strict/nonstrict
  diagnostics.
- `CHAR`, `VARCHAR`, and text-family targets reuse existing raw-text length,
  trimming, truncation, and nonstrict warning behavior.
- Temporal and `YEAR` targets reuse existing storage conversion helpers for
  raw owned text.
- `NULL` into `NOT NULL` follows MySQL `LOAD DATA` row diagnostics for this
  slice: restrictive interpretation fails with `1263 / 22004`; nonrestrictive
  interpretation records a warning and stores the implicit default for the
  descriptor family.
- Omitted columns are initialized through existing descriptor default
  materialization and missing-default adjustment. Missing fields for targeted
  columns do not materialize explicit descriptor defaults; in nonstrict mode
  they use the MySQL `LOAD DATA` missing-field policy described above.

Each raw text buffer is owned exactly once. Helpers that take ownership receive
a dedicated mutable NUL-terminated copy. Helpers that only inspect or mutate a
buffer transfer ownership only through the final `planned_value`.

## Row Shape, SQL Mode, And Warnings

This slice treats interpretation as restrictive when the session is in strict
SQL mode. It treats interpretation as nonrestrictive when no strict mode is
active. `LOCAL` and duplicate-handling modifiers are not admitted as execution
paths and therefore do not relax conversion.

- Exact field count imports normally.
- Too few fields:
  - strict: fail with `1261 / 01000`;
  - nonstrict: append warning `1261` for each missing target field, store
    `NULL` for nullable targets whose effective default is `NULL`, otherwise
    store the target-family implicit value, and continue.
- Too many fields:
  - strict: fail with `1262 / 01000`;
  - nonstrict: append warning `1262`, ignore excess fields, and continue.
- `IGNORE 0 LINES` skips no rows.
- `IGNORE n LINES` counts physical rows before conversion. Skipped rows do not
  produce conversion warnings.
- Successful supported imports report `warning_count == 0` unless admitted
  nonstrict conversion or row-shape warnings occur.

## Physical SQLite Handling

MyLite builds one physical insert statement from descriptors using the same
identifier quoting and stable table naming used by existing insert paths. Row
values are bound as SQLite parameters. The imported filename, logical table
names, column names, and field values are never interpolated into physical SQL.

The implementation should prepare the physical insert once, stream rows, bind
each converted row, step/reset the statement, and commit the statement
transaction only after all rows and post-write checks pass. On any error, the
statement transaction rolls back the entire import.

## Diagnostics

The supported subset uses these diagnostics:

- syntax errors and deferred grammar: existing parse diagnostic;
- `LOCAL` with the current disabled embedded client flow:
  `3948 / 42000`, loading local data disabled;
- missing default schema: `1046 / 3D000`;
- unknown schema: `1049 / 42000`;
- unknown table: `1146 / 42S02`;
- reserved/system target: existing writable-target diagnostic;
- unsupported object kind: existing unsupported diagnostic;
- unknown column-list column: `1054 / 42S22`;
- duplicate column-list target: existing duplicate-column diagnostic;
- missing file or open/stat failure: MySQL-shaped `13 / HY000` file diagnostic
  including the path and OS error when available;
- too few input fields: `1261 / 01000` error or warning;
- too many input fields: `1262 / 01000` error or warning;
- `NULL` into `NOT NULL`: `1263 / 22004` error or warning;
- integer, string, temporal, no-default, duplicate-key, auto-increment, and
  foreign-key diagnostics: existing insert DML diagnostics unless this
  specification gives a `LOAD DATA`-specific row diagnostic;
- allocation failure: existing `MYLITE_NOMEM` diagnostic;
- physical SQLite failure: existing physical row error when SQLite reports an
  unexpected write failure.

## Result Semantics

Successful `LOAD DATA INFILE` returns through the existing non-query result
conventions:

- no row result set;
- `affected_rows` is the number of rows inserted;
- `ROW_COUNT()` observes the inserted row count through the current statement
  context behavior;
- `warning_count` reports accumulated warnings;
- generated auto-increment values update `LAST_INSERT_ID()` and durable
  counters through existing insert semantics.

## Review Checklist

- Parser grammar matches this spec and remains independently authored.
- Runtime target and column resolution remain descriptor-driven.
- File import streams rows and does not materialize the whole file.
- Physical SQL uses stable physical names, quoted identifiers, and bound values.
- Text ownership is single-transfer with no leaks or double frees.
- Strict/nonstrict row-shape and conversion diagnostics match the verified
  MySQL behavior for the admitted subset.
- Successful imports do not mutate logical schema descriptors or file-format
  invariants.
- Compatibility docs describe only the supported subset.
