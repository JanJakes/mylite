# Aggregate functions

Aggregate functions and grouping helpers.

The parser also admits common MySQL aggregate-window `OVER` syntax for the
current `COUNT(*)`, `COUNT(column)`, `COUNT(DISTINCT column)`, supported
row-scalar arguments for `SUM()` / `AVG()` / `MIN()` / `MAX()` / bitwise and
statistical aggregates, and `GROUP_CONCAT(...)`, plus JSON aggregate-window
placeholders such as `JSON_ARRAYAGG(...) OVER ...` and
`JSON_OBJECTAGG(...) OVER ...`. Execution of aggregate-window forms is explicitly
unsupported and returns a deterministic diagnostic. See
[parser aggregate window syntax](../specs/parser-aggregate-window-syntax/specs.md)
and [parser corpus aggregate/window surfaces](../specs/parser-corpus-aggregate-window-surfaces/specs.md)
and
[parser corpus JSON/statistical aggregate window surfaces](../specs/parser-corpus-json-stat-aggregate-window-surfaces/specs.md).

| `ANY_VALUE()` | 🟡 | Limited scalar and row-scalar transparent `ANY_VALUE(expr)` over already-supported scalar/row-scalar expressions, plus limited grouped `ANY_VALUE(column)` over descriptor-backed grouped sources where selected group columns are followed by aggregate-like results; grouped arguments are descriptor columns, representative values are arbitrary when a group contains different candidates, and selected aggregate aliases participate in the existing grouped `HAVING ... GROUP BY group_column` over one base table or the current two-source inner/cartesian/left-outer joined source envelope with optional selected-result `HAVING`; four-fractional-digit text results are produced while the intermediate signed-64 `SUM(expr)` stays in range. `AVG(DISTINCT expr)` and aggregate-window forms parse and reject deterministically. No executable `DISTINCT`, exact decimal widening beyond the signed-64 intermediate envelope, full grouping, aggregate ordering, or executable window forms |
