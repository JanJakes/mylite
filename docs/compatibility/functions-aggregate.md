# Aggregate functions

Aggregate functions and grouping helpers.

The parser also admits common MySQL aggregate-window `OVER` syntax for the
current `COUNT(*)`, `COUNT(column)`, `COUNT(DISTINCT column)`, `SUM()` argument
subset, column-argument `AVG()` / `MIN()` / `MAX()` / bitwise aggregates, and
`GROUP_CONCAT(...)`. Execution of aggregate-window forms is explicitly
unsupported and returns a deterministic diagnostic. See
[parser aggregate window syntax](../specs/parser-aggregate-window-syntax/specs.md).

| Function | Status | Notes |
| --- | --- | --- |
| `ANY_VALUE()` | 🟡 | Limited scalar and row-scalar transparent `ANY_VALUE(expr)` over already-supported scalar/row-scalar expressions, plus limited grouped `ANY_VALUE(column)` over descriptor-backed grouped sources where selected group columns are followed by aggregate-like results; grouped arguments are descriptor columns, representative values are arbitrary when a group contains different candidates, and selected aggregate aliases participate in the existing grouped `HAVING ... IS NULL` / `IS NOT NULL` and `ORDER BY alias [ASC\|DESC]` paths. No mixed ungrouped aggregate form, expression arguments in grouped use, `DISTINCT`, `*`, windows, DML/default/check/generated-column contexts, or deterministic representative-row selection |
| `AVG()` | 🟡 | Limited one-item `SELECT AVG(column) [AS alias]` over one descriptor-backed persistent base table with optional source table alias, source-qualified column argument, and baseline `WHERE`, plus limited grouped form `SELECT group_column, AVG(column) FROM source ... GROUP BY group_column` over one base table or the current two-source inner/cartesian/left-outer joined source envelope with optional selected-result `HAVING`; integer/`NULL` descriptor columns only, with four-fractional-digit text results while the intermediate signed-64 `SUM(column)` stays in range; no expression arguments, `DISTINCT`, exact decimal widening beyond the signed-64 intermediate envelope, full grouping, aggregate ordering, or executable window forms |
| `BIT_AND()` | 🟡 | Limited one-item `SELECT BIT_AND(column) [AS alias]` over one descriptor-backed persistent base table with optional source table alias, source-qualified column argument, and baseline `WHERE`, plus limited grouped form `SELECT group_column, BIT_AND(column) FROM source ... GROUP BY group_column` over one base table or the current two-source inner/cartesian/left-outer joined source envelope; integer/`NULL` descriptor columns only, numeric unsigned-64 semantics with neutral all-ones output for empty/all-`NULL` input, and unsigned decimal text results; no expression arguments, literals, `DISTINCT`, binary-string evaluation, bitwise result `HAVING` predicates, full grouping, aggregate ordering, or executable window forms |
| `BIT_OR()` | 🟡 | Limited one-item `SELECT BIT_OR(column) [AS alias]` over one descriptor-backed persistent base table with optional source table alias, source-qualified column argument, and baseline `WHERE`, plus limited grouped form `SELECT group_column, BIT_OR(column) FROM source ... GROUP BY group_column` over one base table or the current two-source inner/cartesian/left-outer joined source envelope; integer/`NULL` descriptor columns only, numeric unsigned-64 semantics with neutral `0` output for empty/all-`NULL` input, and unsigned decimal text results; no expression arguments, literals, binary-string evaluation, bitwise result `HAVING` predicates, full grouping, aggregate ordering, or executable window forms |
| `BIT_XOR()` | 🟡 | Limited one-item `SELECT BIT_XOR(column) [AS alias]` over one descriptor-backed persistent base table with optional source table alias, source-qualified column argument, and baseline `WHERE`, plus limited grouped form `SELECT group_column, BIT_XOR(column) FROM source ... GROUP BY group_column` over one base table or the current two-source inner/cartesian/left-outer joined source envelope; integer/`NULL` descriptor columns only, numeric unsigned-64 semantics with neutral `0` output for empty/all-`NULL` input, and unsigned decimal text results; no expression arguments, literals, `DISTINCT`, binary-string evaluation, bitwise result `HAVING` predicates, full grouping, aggregate ordering, or executable window forms |
| `COUNT()` | 🟡 | Limited `COUNT(*)` and `COUNT(integer/NULL/boolean literal)` in one-item `SELECT` with no source, `FROM DUAL`, or one descriptor-backed persistent base table, plus `COUNT(*)` over the current joined descriptor-source envelope with optional top-level `DISTINCT`, and limited `COUNT(column)` and `COUNT(DISTINCT column)` including parenthesized descriptor-column form `COUNT(DISTINCT(table.column))` over one descriptor-backed persistent base table; grouped form supports `SELECT group_column, COUNT(*)` and `SELECT group_column, COUNT(column)` over one descriptor-backed persistent base table or the current two-source inner/cartesian/left-outer joined source envelope with optional selected-result `HAVING`; optional select-item alias labels are supported, and optional source table alias, source-qualified column arguments, and baseline `WHERE` are supported for table-backed forms; no general `COUNT(expr)`, joined non-star count forms, grouped `COUNT(DISTINCT)`, full grouping, aggregate ordering, or executable window forms |
| `COUNT(DISTINCT)` | 🟡 | Limited one-item `COUNT(DISTINCT column) [AS alias]` over one descriptor-backed persistent base table with optional source table alias, source-qualified column argument, parenthesized descriptor-column form such as `COUNT(DISTINCT(table.column))`, and baseline `WHERE`; integer/`NULL` descriptor columns only, no multiple expressions, expression arguments beyond parenthesized descriptor columns, literals, grouping, ordering, limiting, or executable window forms |
| `GROUP_CONCAT()` | 🟡 | Limited one-item `SELECT GROUP_CONCAT(column [ORDER BY order_column [ASC\|DESC]] [SEPARATOR 'literal']) [AS alias]` over one descriptor-backed persistent base table with optional source table alias, source-qualified value/order columns, and baseline `WHERE`, plus limited grouped form `SELECT group_column, GROUP_CONCAT(...) FROM table ... GROUP BY group_column` over one base table; integer and nonbinary string descriptor value columns only, aggregate-local order keys require `NOT NULL` integer/`BIT`/`YEAR`/temporal descriptor columns, empty/all-`NULL` input returns `NULL`, and output is byte-capped by session `@@group_concat_max_len` with MySQL-compatible truncation warnings for the supported subset. The parser additionally admits expression-shaped value arguments and expression or multi-key aggregate-local `ORDER BY` lists, but those broader shapes are rejected by the current aggregate planner. No `DISTINCT`, executable expression arguments, executable nullable or string order keys, executable multiple order keys, binary result metadata, full grouping, joins, executable aggregate windows, or metadata threshold behavior |
| `GROUPING()` | ❌ | Distinguish super-aggregate ROLLUP rows from regular rows |
| `MAX()` | 🟡 | Limited one-item `SELECT MAX(column) [AS alias]` over one descriptor-backed persistent base table with optional source table alias, source-qualified column argument, and baseline `WHERE`, plus limited grouped form `SELECT group_column, MAX(column) FROM source ... GROUP BY group_column` over one base table or the current two-source inner/cartesian/left-outer joined source envelope with optional selected-result `HAVING`; integer/`NULL` and nonbinary string descriptor columns only, no expression arguments, `DISTINCT`, full grouping, aggregate ordering, binary string arguments, or executable window forms |
| `MIN()` | 🟡 | Limited one-item `SELECT MIN(column) [AS alias]` over one descriptor-backed persistent base table with optional source table alias, source-qualified column argument, and baseline `WHERE`, plus limited grouped form `SELECT group_column, MIN(column) FROM source ... GROUP BY group_column` over one base table or the current two-source inner/cartesian/left-outer joined source envelope with optional selected-result `HAVING`; integer/`NULL` and nonbinary string descriptor columns only, no expression arguments, `DISTINCT`, full grouping, aggregate ordering, binary string arguments, or executable window forms |
| `STD()` | ❌ | Return population standard deviation |
| `STDDEV()` | ❌ | Return population standard deviation |
| `STDDEV_POP()` | ❌ | Return population standard deviation |
| `STDDEV_SAMP()` | ❌ | Return sample standard deviation |
| `SUM()` | 🟡 | Limited one-item `SELECT SUM(column) [AS alias]` and narrow `SELECT SUM(string_length(column)) [AS alias]` over one descriptor-backed persistent base table with optional source table alias, source-qualified column argument, and baseline `WHERE`, plus limited grouped form `SELECT group_column, SUM(column) FROM source ... GROUP BY group_column` over one base table or the current two-source inner/cartesian/left-outer joined source envelope with optional selected-result `HAVING`, and narrow grouped `SUM(column + column)` over two integer descriptor columns for metadata-size queries; integer/`NULL` descriptor columns or supported string-length row-scalar expressions only, with results limited to MyLite's signed-64 text result envelope; no general expression arguments, `DISTINCT`, exact decimal result widening beyond signed 64 bits, full grouping, aggregate ordering, or executable window forms |
| `VAR_POP()` | ❌ | Return population standard variance |
| `VAR_SAMP()` | ❌ | Return sample variance |
| `VARIANCE()` | ❌ | Return population standard variance |
